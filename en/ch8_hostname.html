Chapter 8

Set the external hostname

Connect Home Assistant to one clear public hostname, and make Home Assistant trust only the right reverse proxy. You will finish both the add-on configuration and the http configuration, and run the acceptance check over two paths: from your local network and from outside.

Having a URL is not the same as signing in safely

external_hostname tells the locally managed Cloudflared add-on which public domain name to send to Home Assistant. But there is a reverse proxy in front of the tunnel, and by default Home Assistant blocks requests that arrive from a proxy it does not trust, so you also have to set use_x_forwarded_for and trusted_proxies correctly.

Two different restarts: after you change configuration.yaml you must restart Home Assistant; pressing Save & Restart in Config writes to Supervisor options and then restarts the Cloudflared Web GUI add-on. Either one can break the connection for a while, so make sure you still have a working local entrance first.
This guide changed nothing in the demo environment: everything here comes from read-only observation and from checking the documentation; nothing was saved, restarted, authorized or created in DNS on the Home Assistant used for the screenshots. The steps below change something only when you run them on your own system.

Understand the hostname and the proxy path first

WhereRole it playsWhat you set
Cloudflare DNS and the edgeTakes the browser's HTTPS connection to the public hostnameThe domain has to use Cloudflare DNS; the locally managed flow creates the matching tunnel DNS route
Cloudflare TunnelConnects out from your house to Cloudflare, with no inbound port opened on the routerFill in external_hostname in the add-on
The Cloudflared add-onSends requests that match the hostname on to Home AssistantIt runs normally and has an edge connection
Home Assistant HTTPDecides whether the original client information a proxy forwards can be trustedTurn on forwarded headers, and trust only the add-on's Docker network range

According to the add-on DOCS, the standard add-on network on Home Assistant OS / Supervisor uses the trusted-proxy range below. It is a network range, not a list of public Cloudflare IPs:

http:
  use_x_forwarded_for: true
  trusted_proxies:
    - 172.30.33.0/24
Do not widen it to every source: the official Home Assistant HTTP documentation warns that only the reverse proxy that connects directly to Home Assistant belongs in the trusted proxy list. Too broad a range gives an untrusted source the chance to forge the forwarded information.

From backup to external acceptance check

  1. Confirm the mode and the domain first

    The external_hostname in this chapter applies to a locally managed tunnel. If Config already holds a tunnel_token, the other options are ignored, so set the public hostname in Cloudflare Zero Trust instead. When you use local mode, confirm the target domain is already managed by your Cloudflare account.

  2. Pick a dedicated hostname

    Your own ha.example.com, for instance. The Config field takes the hostname only: no https://, no port, no path and no trailing slash. Do not copy the example domain either.

  3. Back up configuration.yaml

    Make a Home Assistant backup before you change anything, or at least keep a copy of the current file you can restore. Confirm you can work through the local URL on your home network; if the remote tunnel is your only way in, do not risk a restart.

  4. Merge the proxy settings into the existing http block

    Open /config/configuration.yaml with whatever file editing method you trust. If a top-level http: already exists, merge the two keys into that same block; you cannot create a second http:. A standard add-on installation uses the 172.30.33.0/24 the documentation above specifies.

  5. Check the YAML before you restart Home Assistant

    YAML is indented with spaces, not tabs. Confirm the syntax with the configuration check your current Home Assistant version provides; the menu path can move between versions, so follow the official configuration documentation when you cannot find it. Restart Home Assistant fully only after the check passes.

  6. Confirm local sign-in still works

    Wait for Home Assistant to finish starting, sign in with the local URL you were already using, and read the system log for HTTP configuration errors. If it fails to start, restore the YAML you just changed and leave the tunnel alone.

  7. Fill in external_hostname in Config

    Open Cloudflared Web GUI → Config and put the name you chose into external_hostname. Check the spelling, the domain and the mode once more; the first time you create a locally managed tunnel, you may still have to finish the Cloudflare authorization by following the flow Setup and Logs show you.

  8. Press Save & Restart once you accept what it does

    This step really does write to Supervisor options and restart the add-on, and the tunnel drops briefly. Wait for the Dashboard to come back and confirm there is an edge connection, then read Logs to see whether the DNS route and the connection flow completed.

  9. Test the full URL over mobile data

    Turn Wi-Fi off on your phone and open https://your-hostname. Confirm the certificate is fine, the sign-in page appears, and that after signing in the controls work and the live view keeps updating. Do not test on your home Wi-Fi alone; that proves nothing about the external path.

Authorization data never leaves your hands: the Cloudflare authorization URL drives a sensitive flow that links your account to your domain; tokens, certificates and any log that holds a secret must never be pasted into a chat, a forum or an issue. When you need help, share only a redacted fragment of the error.

Item-by-item checks before you go public

  1. No new inbound port forwarding on the router

    Cloudflare Tunnel connects out from your house, so there is no need to forward 8123 or any other service port to the internet. If you opened a port in the past, confirm nothing else uses it and then remove it the way your router expects.

  2. trusted_proxies stays at the smallest range

    A standard add-on uses 172.30.33.0/24, as the DOCS says; in a non-standard environment, judge from the log and the real topology. Do not trust all of IPv4, your whole home LAN, or Cloudflare edge ranges that never connect to HA directly.

  3. Home Assistant accounts are protected

    Every user has their own account and a strong password, and administrators turn on multi-factor authentication. A tunnel does not make a weak password safe, and it does not replace Home Assistant's own permission controls.

  4. The public name gives nothing else away

    A hostname is not a password, but still keep your address, your name and device model numbers out of it. Before you share a screen or Logs, redact the full hostname, IPs, accounts, the tunnel ID, tokens and the authorization URL.

  5. Any extra Cloudflare protection has a clear plan

    When you need tighter limits, you can evaluate Cloudflare Access separately, but check compatibility with the Home Assistant app, webhooks and your other integrations first. Access is another layer of policy; it does not replace the Home Assistant sign-in.

Acceptance complete: you are done only when both the local and the external entrance work, no inbound port is open, and Logs show no persistent error. A DNS record, or a tunnel that says connected, is not enough on its own.

Common external hostname pitfalls

  1. The browser shows a 400, or the HA log says the proxy is not trusted

    Confirm that use_x_forwarded_for: true and trusted_proxies sit inside the same top-level http:, that the YAML indentation is right, and that you fully restarted Home Assistant after the change. On a non-standard deployment, find the direct proxy address in the log; do not simply widen it to every source.

  2. You get a 502 Bad Gateway

    That usually means the connection from Cloudflared to the origin did not succeed. Confirm Home Assistant works locally first, then check whether you customized the HTTP port or SSL; if you did, the complete http: block has to live directly in configuration.yaml so the add-on can detect it.

  3. The hostname is not found, or opens an old service

    Check the spelling, the DNS zone in your Cloudflare account, and Logs. When the add-on brings up a locally managed route it can overwrite a matching existing DNS record, so do not test with a hostname another service already uses; restore the original DNS first if you have to.

  4. The tunnel is connected, but external_hostname has no effect

    Check whether Config holds a tunnel_token. A token means remotely managed mode and the local options are ignored; go to Cloudflare Zero Trust and check the public hostname and the origin service there.

  5. After sign-in the page keeps dropping, or features are not live

    Confirm that WebSockets work on the Cloudflare domain first, then look at the same moment in the browser and in the HA and add-on logs. Do not start by turning off every security setting; change one thing at a time and test again.

FAQ

Does external_hostname take the full https URL?
No. Enter the hostname only, for example ha.example.com, with no https://, port, path or slash. The full https://ha.example.com is what you use in the browser for the acceptance check.
Why do I have to set trusted_proxies?
Requests pass through Cloudflare and the Cloudflared proxy before they reach Home Assistant. By default Home Assistant does not accept forwarded headers from a proxy it does not trust; you have to trust the direct proxy explicitly before the original client information can be handled safely.
Can I set trusted_proxies to every IP just to get it working?
No. That breaks the trust boundary. A standard add-on uses 172.30.33.0/24, as the DOCS says; in a non-standard environment, read the HA log and your network topology and add only the direct proxy IP you need, or the smallest network range.
After I change configuration.yaml, is restarting the add-on enough?
No. This is Home Assistant's own HTTP configuration, so you check the YAML and then restart Home Assistant. Changing Config and pressing Save & Restart is a separate thing: that restarts the Cloudflared add-on.
Do I have to expose Home Assistant to use the tunnel?
No. According to the add-on DOCS, external_hostname can stay empty and you can use additional_hosts alone. The other way around holds too: if Home Assistant is all you need, do not casually add other services from your local network.

Official sources and version notes

The hostname and the standard network range follow the WoowTech add-on DOCS; Config synchronization and restart behavior follow the Web GUI README. For the trusted-proxy principle, check the official Home Assistant HTTP integration documentation, and for Cloudflare connectivity and DNS routes, defer to the official Cloudflare Tunnel documentation.

Version note: the configuration check and the restart control move between Home Assistant versions, so this chapter does not hard-code a menu path. 172.30.33.0/24 is what this add-on's DOCS specifies for the standard Supervisor network; if your deployment is not standard, do not force it — confirm the direct proxy from the HA log.
