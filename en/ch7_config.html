Chapter 7

Config and Supervisor options

Config is not a second, separate configuration; it is a friendlier entrance to the same set of add-on options. You will read the current values first, change only the fields you have to, and know the scope of the impact before anything actually restarts.

Understand it before you press save

You may see the same fields on the Web GUI's Config page and on the Home Assistant add-on configuration page. These are not two files overwriting each other: the Cloudflared Web GUI reads and writes the add-on's own options through the Supervisor API, and Supervisor options are the single source of truth. A value saved from either side is the same value the other side reads afterwards.

What the action does: Config's Save & Restart is not a preview. It writes to Supervisor options and then restarts the Cloudflared Web GUI add-on; the tunnel connection drops for a short while. Make sure someone at home can help, and avoid any window in which this tunnel is your only way to manage the system remotely.
The safety boundary for this guide: the guide text and the screenshot environment are read-only observation; nobody pressed Save & Restart, re-authorized or changed a tunnel there. What follows describes changes that happen only when you make them on your own Home Assistant.

Supervisor options are the single source of truth

Think of Supervisor options as the official label on the breaker panel at home, and of Config and the add-on configuration page as two doors that read and write that one label. When the two sides disagree, do not keep two tabs open and save from each in turn; refresh first and confirm the last value that saved successfully.

The full flow for changing Config safely

  1. Confirm you still have a local entrance

    Open Home Assistant's local URL from your home Wi-Fi first and confirm you can sign in. If you are away from home and this tunnel is your only way in, do not restart yet; a wrong setting can leave you unable to reach your house.

  2. Open Config in the Cloudflared Web GUI

    Go in through Open Web UI on the add-on page, or through the Cloudflared sidebar entry if you enabled it, then pick Config. Button size or capitalization may differ between versions; follow the Config on the page in front of you.

  3. Work out whether the mode is locally or remotely managed

    If tunnel_token has a value, treat it as a remotely managed tunnel: the public hostname and the routes belong in Cloudflare Zero Trust. Only when there is no token do you work through this chapter's table for the locally managed options such as external_hostname and additional_hosts.

  4. Record the current values and change one kind of setting only

    Write the non-sensitive fields into your own offline notes, the tunnel name and the hostname for example, and never copy down a token or a full authorization URL. Change one kind of setting at a time, say log_level on its own, rather than the hostname, the proxy and the run parameters at once, so you can roll back later.

  5. Check the format field by field

    A hostname is the domain name only: no https://, no path, no trailing slash. An additional service needs a full origin service instead, such as http://192.168.1.20:8080. Leave any advanced field you are unsure about at its current value.

  6. Press Save & Restart only once you understand the impact

    Check that nobody else is relying on remote access, then press Save & Restart. It writes the form into Supervisor options and restarts the add-on; it does not save a draft. Losing the page for a moment is normal, so wait for the add-on to come back up.

  7. Read the values back and check Logs

    Refresh Config and confirm the non-sensitive fields you just changed are still there; then use the Dashboard and Logs to confirm the add-on is running, the tunnel has edge connections, and no fatal or error message keeps repeating.

Never share: tunnel_token, the Cloudflare authorization URL, the contents of a certificate, and a full log that may carry a hostname, an IP, an account or a token are all sensitive. When you ask for help, paste only the fragment you need, and redact secrets and identifying details first.

Two log levels: the add-on's log_level controls the add-on's own output; the tunnel's own verbosity can be adjusted through the allowed run_parameters, using --loglevel. If you are new to this, do not mix the two for now.

Security checks before you save

  1. Confirm there is no public entrance you do not need

    Go through external_hostname and additional_hosts one entry at a time. Do not create a route you have no reason to use from outside, and above all avoid exposing your router, your NAS or another admin back end directly.

  2. Check that no sensitive field has leaked

    A password manager may hold a token; a chat app, a public issue, a screenshot and a shared document may not. If a token has leaked, revoke or rotate it on the Cloudflare side instead of only deleting the message.

  3. Avoid a broad catch-all

    catch_all_service and wildcard DNS widen what can be reached. If one Home Assistant hostname is all you need, use explicit rules; do not open a wildcard entrance now for the sake of "convenience later."

  4. Keep each service's own sign-in protection

    The tunnel solves the connection from Cloudflare to your home; it does not automatically give every origin the sign-in and permissions that suit you. Home Assistant still needs individual accounts, strong passwords and multi-factor authentication, and so does every other service.

  5. Arrange a way to roll back

    Make sure the local URL works, and write down the last non-sensitive configuration that was known good. Before you work remotely, decide in advance who can use the local entrance at home to recover if the tunnel does not come back up.

Common Config pitfalls

  1. A field reverts after you save

    Do not press save again and again. Refresh both the Web GUI and the add-on configuration page, and check whether another stale tab overwrote it later. Keep a single editing entrance open, make one small change again and wait for the restart to finish.

  2. The Web GUI will not open for a while after you press it

    Save & Restart really does restart the add-on, and a short Ingress outage is expected. Go back to the add-on page for the state and Logs; if it restarts over and over, use the first clear validation or fatal message to roll back the field you just changed.

  3. You changed the hostname and nothing happened

    Check whether tunnel_token is filled in. A remotely managed tunnel ignores the other locally managed settings; change the hostname and the public hostname routes in Cloudflare Zero Trust.

  4. Too many log lines, or nothing stands out

    Reproduce it once on info and note the time; switch to debug briefly if you have to. Capture only the slice around the error, redact the hostname, IP, token, certificate and authorization URL, and set it back to info when you are done.

  5. Configuration validation fails

    Compare the field formats: a hostname carries no protocol, an additional host's service needs http:// or https://, and a boolean is not text. Restore the last value that worked, and do not guess at fields that are not in the schema.

FAQ

Config or the add-on configuration page: which one is real?
Both read and write the same Supervisor options; the options themselves are the single source of truth. Do not edit in two stale tabs at once — save, refresh and cross-check.
Can Save & Restart save without restarting?
The button is designed to write Supervisor options and then restart the add-on. If a short tunnel outage is not acceptable right now, do not press it; work in a maintenance window instead.
Should I leave log_level on debug all the time?
We do not recommend it. The upstream documentation recommends the default info for normal use. debug suits short troubleshooting sessions: it produces more, and it needs more checking for sensitive data before you share it.
If I only want to expose other services, can I leave external_hostname empty?
Yes. A locally managed tunnel lets you leave external_hostname empty and set only additional_hosts. Every extra service still goes through the necessity and security checks in Chapter 9 first.
With tunnel_token set, do I still fill in additional_hosts in Config?
Do not rely on those fields. Per the add-on documentation, the remotely managed mode with tunnel_token set ignores the other options; manage public hostnames and service routes in the Cloudflare dashboard.

Official sources and version notes

This chapter follows the WoowTech Cloudflared Web GUI README for Supervisor options as the single source of truth, the Config sync and the Save & Restart behavior, and its add-on DOCS for what each option does. For advanced parameters, check only the official Cloudflare Tunnel run parameters documentation.

Version note: button positions and wording in Home Assistant and the Web GUI can shift between versions, but the two product behaviors this chapter's decisions rest on do not: Supervisor options are the single source of truth, and pressing Save & Restart writes and then restarts.
