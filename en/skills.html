WoowTech Skill Handbook

Teach your AI agent the craft of Cloudflare

A skill is a "work manual" written for an AI: one folder, one SKILL.md, and when the matching situation comes up the agent opens it and follows it. This handbook picks 8 Cloudflare-related skills that actually run, and adds an install quick reference, compatibility notes, safety rules and the SKILL.md spec. Workers/Pages deploys, DNS automation, tunnel management and Zero Trust policy generation are all covered.

How this was researched: the star counts and collection sizes in this handbook are the public GitHub figures on 2026-08-20, the day of the survey; they move over time, so open the original repo and check again before you install.

What a skill is and why you'd install one

Think of an AI agent as a very capable cloud engineer: it knows Workers syntax, the Wrangler CLI and the REST API — but it cannot read your mind about the way things are done in your Cloudflare account. A skill is the working SOP you write for the agent: which situation, which steps to follow, which pitfalls to avoid, all written into one Markdown file. Put it in the skills folder and the agent follows it.

  • Install what other people have written: Cloudflare's own, community and platform-specific collections are already written; install one and the agent knows it.
  • Write your own later: package your team's deploy conventions, naming rules and environment-variable layout into a skill, and a new project picks them up automatically.

A skill is, at heart, "instructions fed to the agent" — installing a third-party skill gives text you did not write a chance to direct your Cloudflare token, so be sure to follow all four rules in this handbook's Safety rules.

How to install (the 3-minute version)

The skill ecosystem has two ways to install today: drop the folder into Claude Code's ~/.claude/skills/, or use another agent platform's plugin/skill management UI. Using Claude Code as the example:

  1. Clone into the skills folder

    Use ~/.claude/skills/ for yourself; use .claude/skills/ for a project (it is committed with the repo).

    cd ~/.claude/skills
git clone https://github.com/cloudflare/skills cloudflare-skills

  2. Check where SKILL.md sits

    Claude Code scans the folder recursively for each skill's SKILL.md. In a collection repo every subfolder is one skill.

  3. Restart or reload the agent

    Skills are loaded when the session starts. After the restart, ask "which cloudflare-related skills do I have right now?" and check the list.

  4. Test the trigger with one sentence

    State a request that matches the situation the skill's description names, and see whether the agent reaches for it on its own.

Tip: a pure-Markdown skill runs on almost every agent (Claude Code, Codex, Cursor, OpenCode, Pi Agent); for one that depends on hooks, scripts or a particular CLI, read the compatibility section of that skill's README first.

Compatibility notes

The SKILL.md spec has been adopted by Claude Code, Codex, Gemini CLI, Cursor, OpenCode, Pi Agent and others, so a pure-Markdown skill runs almost anywhere. Only three situations make it "degrade":

  • It depends on a Claude Code-only mechanism (hooks, plugin commands, dispatching work to a subagent) — the skill text is still readable, but the automatic triggering may be incomplete.
  • It depends on a particular MCP / SaaS account — without that service connected it does nothing; almost every Cloudflare skill assumes you have installed cloudflare/mcp-server-cloudflare or can use Wrangler, so check before you install.
  • scripts/ needs a runtime you do not have — a skill that needs Node, Wrangler, Terraform or jq will not run if they are not installed locally; a pure-Markdown skill is the most compatible.
Concept: the first rule for picking a skill is not the star count, it is "do you have the environment it assumes". 90% of Cloudflare skills assume you have Wrangler + an API Token.

Safety rules

Warning: a skill is, at heart, "instructions fed to the agent". Installing a third-party Cloudflare skill = giving text you did not write a chance to direct your Cloudflare token, which is the same as lending out your account permissions.
  • Read it before you install it: open SKILL.md and read it through, watching especially for instructions telling the agent to "run this curl", "delete that record" or "set that secret". Or have the agent read it to you: "Read this skill first, list what it would do to my Cloudflare account and whether there is any risk, and install it only once I agree."
  • Give the token the smallest scope: for a DNS skill grant only Zone.DNS:Edit, never the Global API Key. If the skill turns out to be wrong, the damage is limited.
  • Pin the version in production: git clone --branch v1.2.0, or pin a commit, so an upstream change cannot upgrade you without your noticing.
  • Stars = popularity, not safety: a popular collection still has to be read for which permissions it takes and what it does with them. Cloudflare is production infrastructure, and a mistake there costs far more than one on your home Home Assistant.

SKILL.md spec quick reference

The minimal skeleton of one Cloudflare skill:

cf-tunnel-quickstart/
├── SKILL.md          ← the only required file
├── references/       ← optional: excerpts from the official docs
└── scripts/          ← optional: wrangler and curl examples

# SKILL.md contents
---
name: cf-tunnel-quickstart
description: Triggers when the user asks to create a Cloudflare Tunnel, add a hostname,
  or expose an internal service on the example.com domain.
  Covers cloudflared install, tunnel creation, DNS CNAME and Access policy.
license: MIT
compatibility: claude-code, cursor, codex, opencode
---

# Cloudflare Tunnel quickstart

## When to use it
(instructions written for the agent, as if you were briefing a new colleague)
FieldRequiredWhat it means
nameYesLowercase letters, digits and hyphens, 1–64 characters.
descriptionYesWhat it does + when it triggers. The agent decides from this line whether to load the skill, so put the words a user would actually say into it (for example "create a tunnel" or "add a hostname").
licenseNoMIT / Apache-2.0 is recommended, so other people can fork it with confidence.
compatibilityNoList the agents you have actually tested, so users can filter.
allowed-toolsNoAn allowlist of the tools the agent may use, for example [Read, Bash, WebFetch].

Convention: keep SKILL.md short (< 500 lines), put long stretches of official documentation in references/ and scripts in scripts/, and read them only when they are needed so you do not blow up the context.

Tip: the Cloudflare RFC agent-skills-discovery-rfc is pushing /.well-known/agent-skills so an agent can discover the available skills on a site automatically — in future your own site could serve skills to a customer's agent.

FAQ

What is the difference between the official Cloudflare skills and community skills?
The official cloudflare/skills focuses on "building things on Cloudflare" — Workers, Pages, D1, R2 and KV development; community skills fill in "operations" and things like tunnel/DNS/Access. In practice you install both: the official set is the skeleton, the community set is the flesh.
The skill is installed but the agent never triggers it?
Three causes: 1) you did not restart the agent (skills load when the session starts); 2) the description does not cover the way you phrased it — name it directly, "use cloudflare-skill to create a tunnel for me"; 3) on Claude Code, check that the ~/.claude/skills/ path is right and that recursion with depth > 1 is allowed.
What happens if I install too many skills?
Every skill's name + description takes up context in the system prompt; at 30 or more the agent gets distracted and it costs more. The rule: keep what you use, remove what you tried and never used. For Cloudflare, keeping 1 platform skill + 1 tunnel/DNS skill covers 80% of the work.
How do an MCP server and a skill relate?
A skill is the knowledge of "how it should be done" (markdown for the agent to read); an MCP server is the ability to "do it" (tools for the agent to call). cloudflare/mcp-server-cloudflare provides the tools (GET zones, PUT records...), and a Cloudflare skill teaches the agent "which tool to use when, in what order, and how to check the result" — best practice is to use both together.
How do I package my company's or a customer's Cloudflare conventions into a skill of my own?
Use the anthropics/skills repo's skill-creator to start a new skeleton, and write your "naming rules, standard tunnel configuration, Access policy template and Wrangler bindings conventions" into SKILL.md. Put it in a private GitHub repo and have every internal agent clone it into .claude/skills/: write it once and the whole company is consistent.
How do I tell whether a skill suits me?
Four checkpoints: 1) whether the first description line in SKILL.md is specific; 2) whether a compatibility: field names the agents it was tested on; 3) whether you have the runtime scripts/ needs; 4) whether the issues / PRs are still active (a community skill with no commit for six months is usually out of date).
