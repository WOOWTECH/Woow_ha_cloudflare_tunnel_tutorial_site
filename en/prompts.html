Let your AI agent drive Cloudflare in plain language

Cloudflare ships an official cloudflare/mcp-server-cloudflare, and REST API v4 (api.cloudflare.com/client/v4/) covers the whole resource set. This handbook collects 46 working prompts across DNS, Tunnel, Access, Workers, Pages, WAF, Analytics and troubleshooting. Every one of them is ready to copy into Claude Code, Cursor or any AI agent that speaks MCP or curl. Take back the time you spend clicking through the dashboard.

What this handbook is

This handbook earns its place as soon as your AI agent can do any one of the following:

  • It has Cloudflare's official MCP server installed (cloudflare/mcp-server-cloudflare): the agent calls a tool directly.
  • It can curl or fetch the REST API: any model that can run a shell or make an HTTP request can reach https://api.cloudflare.com/client/v4/.
  • It can call the Wrangler CLI: the Workers and Pages deploy prompts take that route.

The prompts deliberately avoid "write me a curl command". Describe the goal and let the agent pick the right tool: anything the dashboard can do, the agent can do too, including bulk edits, audits and automation across resources.

Concept: a prompt is not valuable because it is a word-perfect incantation. It is valuable because it states the goal, the scope, the acceptance check and the risk in one go. Copying one as it stands works; editing it to match your own zone and account works better.

How to use these prompts

  1. Prepare an API token (not the Global Key)

    Cloudflare Dashboard → My Profile → API Tokens → create a token with the smallest scope that does the job (for example Zone.DNS:Edit, Zone.Zone:Read).

  2. Hand the token to the agent

    Use the environment variable CF_API_TOKEN (curl sends it as Authorization: Bearer); Wrangler reads CLOUDFLARE_API_TOKEN; for the MCP server, follow the official README.

  3. Copy one prompt

    Substitute your own zone name, hostname and tunnel ID, then paste it into the agent. Every prompt here ends with "Answer in English." — keep that line.

  4. Keep the habit of "report first, act second"

    Write every request that changes a resource as "give me a dry-run summary first, I will confirm before you apply it". A wrong DNS, Access or WAF edit hits your public service immediately — that one sentence is the cheapest insurance you have.

Security: never paste a token into a shared message and never commit one to a repo; if one leaks, revoke it in the dashboard right away. In production we recommend a Scoped Token limited to a single zone and a single permission group.

1 · DNS record management

Cloudflare's DNS operations run through /zones/{zone_id}/dns_records. For bulk work on A, CNAME and TXT records it is ten times faster than the dashboard.

List every DNS record in the example.com zone and output type / name / content / proxied / TTL as a markdown table. Call out any hostname that has more than one record. Answer in English.

API: GET /zones/{zone_id}/dns_records.

Add a CNAME to example.com: ha pointing at <tunnel-uuid>.cfargotunnel.com, proxied on. Before you add it, confirm no record of the same name exists; if one does, list it and let me decide whether to overwrite. Answer in English.

API: POST /zones/{zone_id}/dns_records; to overwrite, use PUT with the record_id.

Under example.com, list every TXT record matching _acme-challenge.* and delete the ones that have not been updated in over 24 hours (the certificate was issued long ago). Show me the list before you delete anything. Answer in English.

Most useful for clearing out leftover Let's Encrypt validation records in bulk.

Run a DNS health check on example.com: find A / AAAA records that are not proxied (they expose the origin IP), TTLs set to Auto that resolve to under 300 seconds, and CNAMEs pointing at a tunnel or worker route that no longer exists. Give me a list of what to fix. Answer in English.

I want old.example.com to 302-redirect to https://new.example.com/$1. Build it with Cloudflare Bulk Redirect or Redirect Rules, and confirm the redirect also applies to the query string. Answer in English.

The Bulk Redirect API is at /accounts/{account_id}/rules/lists.

Set up the email DNS records for example.com: SPF (v=spf1 include:_spf.google.com ~all), DKIM (selector google) and DMARC (v=DMARC1; p=quarantine; rua=mailto:dmarc@example.com). If a record of the same name already exists, list it first. Answer in English.

2 · Tunnel and hostname setup

In the API, Cloudflare Tunnel lives at /accounts/{account_id}/cfd_tunnel; a hostname is an ingress entry inside the tunnel. This is the section to use for multi-host routing.

List every Cloudflare Tunnel in my account: ID, name, status and connection count. Put the ones whose status is not healthy first, and include a link straight into the dashboard for each. Answer in English.

API: GET /accounts/{account_id}/cfd_tunnel.

Create a new tunnel called home-lab with this ingress: ha.example.com → http://192.168.1.10:8123, z2m.example.com → http://192.168.1.10:8080, and a default catch-all returning http_status:404. Create the matching DNS CNAMEs while you are at it. Answer in English.

On the existing tunnel home-lab, add the hostname nas.example.com pointing at https://192.168.1.20:5001 on my local network. The NAS uses a self-signed certificate, so set originRequest.noTLSVerify to true. When you are done, print the full config so I can check it. Answer in English.

Across every hostname on tunnel home-lab, find the ones with no traffic in the past 7 days (cross-check with the Analytics API). They are probably old services I forgot to delete. List them and let me decide whether to remove them. Answer in English.

Produce a configuration backup for tunnel home-lab: export the full config, the associated DNS records and the associated Access apps together as one JSON file, so I can keep a copy off-site. Answer in English.

Delete tunnel old-test-tunnel. Before you delete it, confirm it has no active connections and list every DNS record pointing at it that has to be cleared as well. Report back once it is all done. Answer in English.

3 · Access rules (Zero Trust)

The Cloudflare Access API runs through /accounts/{account_id}/access/apps and /access/policies. Allow lists for the people you live with, and SSO policies, are handled here.

In Zero Trust, create an Access application for ha.example.com with type self-hosted. Add one allow policy: permit only the emails me@example.com and wife@example.com, a 24-hour session, and Google plus One-time PIN as the identity providers. Answer in English.

List every Access app in my Zero Trust account: domain, type, associated policies and sign-ins over the past 30 days. Put the ones nobody has ever signed in to first — they may be configured but never published. Answer in English.

On the ha.example.com app, add a policy: only the main account may reach the path /config/*, while the family email allow list may see only /lovelace/*. Implement it with a combination of include and require. Give me a dry-run summary of the change. Answer in English.

Create a "temporary guest" Access policy for ha.example.com: accept any email over OTP, but with a session of only 4 hours and access limited to the path /lovelace/guest. I want it for letting a contractor check a status page remotely. Answer in English.

Add a country restriction to every Access app: allow only source country = TW and block everything else, down to the Access sign-in page. Implement it with device posture rules or IP geolocation, whichever is more reliable. Answer in English.

Wire Google Workspace SSO into Access: register a SAML / OIDC provider for the @example.com domain, make Workspace the default sign-in for every app afterwards, and leave OTP as the fallback for family Gmail accounts. Give me a test link when it is set up. Answer in English.

4 · Workers deploy

Workers go through wrangler deploy or the API at /accounts/{account_id}/workers/scripts/{name}. Paired with KV, D1 and R2 they are a good fit for serverless logic at the edge.

List every Workers script in my account: name, routes, requests over the past 24 hours and error rate. Put anything with an error rate > 1% first. Answer in English.

Pull the metrics from the GraphQL Analytics API.

Write a Worker called ha-webhook-proxy: take a POST request, validate the X-Auth-Token header, then forward it to https://ha.example.com/api/webhook/xxx on my local network. Set the route to webhook.example.com/*. Use wrangler init and wrangler deploy. Answer in English.

I have a Worker called image-optim. Add a KV binding to the existing KV namespace IMG_CACHE and update wrangler.toml. Deploy the change to preview; do not push straight to production. Answer in English.

Set the secrets for Worker api-gateway: take UPSTREAM_TOKEN from my environment variables, and generate a 32-byte random hex value for SIGNING_KEY. Use wrangler secret put; do not let them land in wrangler.toml. Answer in English.

Show me the error log tail for Worker api-gateway over the past hour, filtered to status >= 500. Capture it with wrangler tail --format=json and pretty-print the output. Answer in English.

Migrate the existing Worker legacy-api from Service Worker syntax to a Module Worker: turn addEventListener('fetch', ...) into export default { fetch(...) }, and move it to TypeScript while you are there. When it is done, run wrangler dev so I can test it locally. Answer in English.

5 · Pages deploy

Pages pushes build output straight up with wrangler pages deploy, or you manage projects through the API at /accounts/{account_id}/pages/projects. It suits static sites plus Functions.

I have just built into ./dist. Deploy it with wrangler pages deploy ./dist --project-name=my-blog and set the custom domain to blog.example.com (create the DNS record too if it does not exist yet). Answer in English.

List the last 10 deployments of Pages project my-blog: id, branch, commit, status and build time. For the failed ones, expand the first line of the error message. Answer in English.

Roll back the last production deployment of Pages project my-blog: find the previous deployment with status=success and promote it to current with the promote API. Give me a diff summary before you act. Answer in English.

Create a new Pages project docs-site: connect the GitHub repo myorg/docs, build command npm run build, output dist, production branch main, and preview every PR. Set the custom domain to docs.example.com. Answer in English.

Add a Functions middleware to Pages project my-blog that hands every /admin/* path to Cloudflare Access for protection. Produce the matching Access application configuration as well. Answer in English.

6 · Firewall / WAF rules

Firewall runs through /zones/{zone_id}/rulesets (the current API) or the older /firewall/rules; Rate Limit runs through /rate_limits. Conditions are written in Expression syntax.

Add a WAF Custom Rule to example.com: (cf.threat_score gt 20 or ip.geoip.country in {"CN" "RU" "KP"}) and not http.request.uri.path contains "/api/webhook", action = Managed Challenge. Before you add it, tell me where it will sit in the zone's current rule order. Answer in English.

List every WAF rule currently on example.com (Custom + Managed + Rate Limits): id, expression, action, last hit time and hits over the last 24h. Put the ones with zero hits last — they may be safe to delete. Answer in English.

Add a rate limit for ha.example.com: if one IP hits /auth/* more than 10 times a minute, block it for an hour. That keeps brute-force attempts off the Home Assistant sign-in. Answer in English.

Turn on Bot Fight Mode (the free tier) and the Cloudflare Managed Ruleset under Managed Rules for example.com. Before you enable them, tell me which legitimate tools they might catch by mistake (an uptime monitor, for example); I will confirm before you switch them on. Answer in English.

Set the SSL/TLS mode for ha.example.com to Full (strict), and turn on Always Use HTTPS, Automatic HTTPS Rewrites and HSTS (max-age 6 months, including subdomains). Confirm the origin certificate is valid before you change anything. Answer in English.

Build an IP Access Rule allow list: add my home static IP 1.2.3.4 to the whitelist, and add the office IP 5.6.7.8/32 as well. WAF rules can reference the list afterwards. Answer in English.

7 · Analytics queries

Cloudflare analytics run on the GraphQL Analytics API (/graphql). Same data as the dashboard, but you can script it and pull it on a schedule.

Use the GraphQL Analytics API to pull request statistics for example.com over the past 24 hours: total requests, cached requests, cache hit ratio, bandwidth and the top 10 status codes. Output it as a markdown table. Answer in English.

List the Access sign-in records for ha.example.com over the past 7 days: user email, time, source IP, country and user agent. Flag the suspicious ones (the middle of the night, an unusual IP, repeated failures). Answer in English.

Give me a WAF attack summary for example.com over the past 30 days: the top 10 blocked countries, the top 10 blocked rules, and the URL paths that triggered rules most often. Output a short narrative plus a table, ready to paste into a monthly client report. Answer in English.

For Worker api-gateway, give me 15-minute buckets over the past 6 hours of invocation count, CPU time p50/p99 and error rate as line data, output as JSON I can plot directly (timestamp, value). Answer in English.

Query across every zone: which zones had a 5xx error rate > 5% over the past 7 days? Sort the list by error rate, and bring a sample trace for the top 5 errors with it. Answer in English.

8 · Troubleshooting

A tunnel that drops, DNS that has not taken effect, Access that keeps signing people out, a Worker returning 5xx — let the agent finish the diagnosis before you touch anything.

ha.example.com keeps returning 502. Run a full diagnosis: whether the DNS record is correct, the state of the tunnel connections, the matching ingress config, whether the origin is reachable, and the Cloudflare edge error log for the past 10 minutes. Give me a markdown diagnosis report. Answer in English.

Cloudflare shows tunnel home-lab as degraded, with 1 edge connection instead of 4. Check whether the cloudflared version is too old, what edge_ip_version is set to, and whether my home network blocks QUIC or UDP. Give me a repair recommendation. Answer in English.

I have just changed the CNAME for ha.example.com, but dig still returns the old value. Please:
1) check whether the record on Cloudflare has updated
2) test propagation from several public DNS resolvers (1.1.1.1, 8.8.8.8, 9.9.9.9)
3) check whether the TTL is set too long. Answer in English.

Someone in my family reports that Access keeps throwing them out of ha.example.com and making them sign in again. Search the past 24 hours of Access logs for that email's sign-in records, and work out whether the session duration is set too short or a require rule is being triggered. Answer in English.

Worker api-gateway has been throwing far more 5xx since early this morning. Use wrangler tail to capture the errors from the past 15 minutes, find the exception message that repeats most, and check in the dashboard whether it is hitting the CPU time or subrequest limit. Answer in English.

Universal SSL on example.com is stuck at pending. Please:
1) list the zone status and the nameserver settings
2) check whether a CAA record is blocking Cloudflare or Let's Encrypt
3) confirm that both the root and the www CNAME point to Cloudflare. Once it is fixed, re-trigger issuance without waiting to be asked. Answer in English.

Prompt-writing cheat sheet

One change to a Cloudflare resource reaches your public service straight away, so these prompts need more guardrails than home automation does. Across all 46, the pattern comes down to five moves:

Say thisNot thisWhy
Name the zone or account: "under the example.com zone…" "Add a DNS record for me" A Cloudflare token often covers several zones; without a name, the agent guesses wrong.
Ask for a dry run first: "give me a diff or preview, I will confirm before you apply it" "Just change production" A wrong DNS or WAF edit hits your public service immediately.
State the acceptance check: "when you are done, curl ha.example.com once and confirm a 200" Leaving verification out No verification means you are guessing; if the agent is willing to run the check, let it.
Limit the scope: "only the /config/* path" "Apply it to every path" The wider an Access or WAF rule reaches, the more it catches by mistake.
Say what happens on failure: "if a record of the same name exists, let me choose whether to overwrite" Assuming everything goes well On a duplicate resource the Cloudflare API either errors or overwrites; decide up front.

FAQ

Where is Cloudflare's official MCP server, and can I use it today?
Cloudflare's official cloudflare/mcp-server-cloudflare gives you tools for Workers, KV, R2, D1 and Analytics, among others; the Claude environment behind this site also has cloudflare-platform-mcp installed. If your agent does not support MCP, calling the REST API with curl gets you the same result.
What is the difference between a Global API Key and an API token?
A Global API Key is a master key: it carries the same rights as the account owner. An API token can be scoped (which zone or account, which permissions). Always use a token, never the Global Key. Create a token → tick only the permissions the task in front of you needs → bind an IP filter to make it safer still.
When should I use Wrangler and when the curl API?
Use Wrangler for Workers and Pages deploys and for tailing logs (it gives you hot reload and bindings management). Use the REST API for resource work such as DNS, Access, WAF and Analytics (finer-grained, and scriptable). The Cloudflare MCP server mostly wraps REST.
What if the agent makes a mess of my zone?
Two layers of insurance: 1) give the token the smallest scope possible, because what it cannot reach it cannot touch; 2) always write "give me a diff or preview, I will confirm before you apply it" into the prompt. If a wrong change does happen, Cloudflare Audit Logs (Enterprise) or the change history in the dashboard will restore most settings.
How do I automate these prompts in CI?
In CI, drop the LLM from the middle. Turn the prompt into Terraform (the cloudflare/cloudflare provider) or a plain curl script. An LLM suits interactive exploration and one-off operations; for changes that repeat, only IaC is stable and reviewable.
