Chapter 2

Install the Cloudflared Web GUI

Add the WoowTech repository to the Home Assistant Apps store, check the source and the hardware compatibility, and only then install. This chapter only gets the Web GUI opening with a blank configuration. It creates no tunnel, authorizes nothing with Cloudflare, and adds no public hostname.

Install the right package in the right place

The Cloudflared Web GUI is not an ordinary Home Assistant integration. It is a third-party App managed by Supervisor (formerly called add-ons). You have to add its repository first, so that the Apps store can fetch the package information and the image; pasting the GitHub URL into the integrations page, into HACS or into your browser's address bar installs nothing.

When this chapter is done: the add-on detail page shows Cloudflared Web GUI, the add-on starts, and you can open the Web UI from Home Assistant. With the configuration left blank, the WoowTech documentation says the Web GUI keeps running while the tunnel stays stopped.
A word on third-party software: Home Assistant states plainly that it cannot guarantee the quality or the security of third-party add-ons. Before you install, check the GitHub organization, the full repository URL and the project documentation; do not install a similarly named package from the search results.

Repository, add-on and Ingress each do one thing

ItemWhat it is forDoes this step create a tunnel

This add-on's Web GUI runs through Ingress on the container-internal port 8099, and the project configuration never asks you to map it to the outside. Dashboard, Setup, Config and Logs are admin pages inside the same add-on, so the admin interface needs no router port forwarding.

Do not expose the admin interface yourself: do not add router forwarding, a Cloudflare public hostname or a reverse proxy for 8099. The right entrance is Open Web UI on the Home Assistant add-on detail page, or the sidebar entry once you turn it on.

Add the repository manually and install

  1. Make sure you are on the right Home Assistant

    Check the browser URL and the name of the Home Assistant you are signed in to, so you do not install on a test machine or on the host your family uses. Go to Apps under Settings; another language or an older version may show "Add-ons" instead. If there is no Apps section at all, go back to Chapter 1 and confirm your installation type.

  2. Open the Apps store

    On the Apps page, choose Install app or App store. The wording of that entrance differs slightly between Home Assistant versions; what you want is the store page where you can search Apps and where a more-options menu sits in the top right.

  3. Open the Repositories dialog

    Choose the three-dot menu in the top right, then Repositories. Do not paste the URL straight into the store's search box; the search box only filters the Apps it already knows about.

  4. Paste the one correct repository URL

    Paste the HTTPS clone URL below in full, check that it starts with https://github.com/WOOWTECH/ and ends with Woow_ha_cloudflare_tunnel_webgui, then choose Add.

    https://github.com/WOOWTECH/Woow_ha_cloudflare_tunnel_webgui

  5. Refresh and check the add-on card

    After you close the repository dialog, refresh the browser if the new card has not shown up in the store yet. Once you find Cloudflared Web GUI, open its detail page and read the description first, and check that the source links back to the WoowTech repository. Do not judge by the icon alone.

  6. Install the add-on

    On the correct detail page, choose Install and wait for Home Assistant to finish downloading and creating it. This can take a few minutes, depending on your host and your network speed; do not press Install repeatedly, and do not power the machine off while it runs.

  7. Leave the configuration blank and start it

    When the install finishes, do not fill in external_hostname, additional_hosts or tunnel_token yet: choose Start. Per the project documentation, a completely blank configuration keeps the Web GUI open and the tunnel stopped, which is exactly what the read-only tour in the next chapter needs.

The sidebar entry is an optional shortcut: you can turn on "Show in sidebar" to make it easier to get back to later; even with it off, you can still go in through Open Web UI on the add-on detail page. That toggle does not put the Web GUI on the public internet.
Where this chapter stops: stop once you see the add-on running. Do not click the authorization link in Setup, do not type a hostname or a token into Config, and do not press Save & Restart.

Save & Restart really does change settings: the button in the Web GUI writes to Supervisor options through the Supervisor API and then restarts the add-on. It is not a "check the format" or a "next" button. After the restart it may sign in, create the tunnel and add a DNS route. Do not press it before you have worked through the configuration checks in the later chapters.
The capture environment was not modified: making this guide meant looking at existing pages read-only. We did not install, start, save, restart or authorize anything on the Home Assistant we captured. The steps above produce changes only when you run them on your own system.

Acceptance checklist after install

  1. The repository entry is correct

    The URL in the Repositories list matches the code block in this chapter character for character, with no extra whitespace, no typo and no look-alike repository.

  2. The add-on really is installed

    From the Apps list you can open the Cloudflared Web GUI detail page, and it shows add-on management controls such as start, stop, configuration or Open Web UI, rather than only the store's install button.

  3. The add-on starts with a blank configuration

    After you start it, the add-on status does not sit at "starting" indefinitely. With a completely blank configuration, a tunnel that is not running is the expected behavior of this fork, so do not put in any hostname just to make a message go away.

  4. The Web UI entrance exists

    The detail page shows Open Web UI, or Cloudflared already appears in the sidebar. For now, just confirm the entrance: do not authorize anything and do not save.

  5. No extra network changes

    You have not added router port forwarding, a Cloudflare DNS record, a public hostname or a reverse proxy rule.

  6. No sensitive data has leaked

    You have not made any private screen public beyond the repository itself; above all, you have not shared the authorization URL, the tunnel token, the full Logs, an account or an internal IP address.

Acceptance passed: the next chapter opens the Web GUI through Ingress for the first time. You only learn to recognize Dashboard, Setup, Config and Logs, and you save nothing.

Common install pitfalls

  1. There is no Repositories option

    Check that you are on the Apps store page, not on Devices & services, in HACS or on some add-on's configuration page. If the whole Apps section is missing, check your installation type; do not try to use HACS in place of a Supervisor add-on.

  2. The add-on does not show up after you add the repository

    As Home Assistant recommends, refresh the browser first, then go back to the Apps store and look again. If it is still missing, check the repository URL once more; a third-party repository can also fail to appear when its configuration data is invalid.

  3. It says unsupported, or there is no installable version

    Compare your system architecture with the aarch64 and amd64 the project currently supports. If your architecture does not match, stop: do not download an image for another architecture and force it in.

  4. The install never finishes

    Keep the host powered and the network stable, come back to the add-on detail page later and check the status, then look for a download or disk-space error in the system logs related to Supervisor. Redact the hostname, the IP address, private repository details and any credentials before you share an error.

  5. It starts and then stops

    First confirm that what you installed is the WoowTech Web GUI version, then read the last few lines of the log on the add-on detail page. With a blank configuration this fork should keep the Web GUI running; if it still stops, write down the version, the architecture and the redacted error, and do not start by filling in a fake hostname or token.

  6. The Open Web UI button does not work

    Confirm that the add-on has finished starting, refresh Home Assistant and try again; you can also turn the sidebar option off and back on. Do not switch to connecting to 8099 directly: Ingress is the entrance protected by the Home Assistant sign-in.

Install FAQ

Is the Cloudflared Web GUI an official Home Assistant add-on?
No. It is a third-party repository maintained by WoowTech, and its tunnel core is forked from the upstream homeassistant-apps/app-cloudflared. Home Assistant also warns that you have to judge the quality and the security of third-party add-ons yourself.
Can I install it from HACS?
No, you cannot use HACS in place of the flow in this chapter. This is an add-on managed by Supervisor: you add the repository in the Home Assistant Apps store and install it from there.
Do I have to fill in a hostname right after installing?
No. The particular behavior of this fork is that a completely blank configuration keeps the Web GUI and stops the tunnel, so you can open the interface and do your first round of planning. Do not type in fake data just to make the screen "look complete".
Do I need to open 8099 or 8123 on the router?
No. 8099 is the Web GUI's internal Ingress port, and a Cloudflare Tunnel is dialed out by the connector. This guide does not require you to add inbound port forwarding for Home Assistant.
Can I press Save & Restart now, just to see?
Do not treat it as a test button. It writes to Supervisor options and then restarts the add-on, and it may go on to sign in, create the tunnel or change DNS. Wait until a later chapter has you check the real configuration.
The menu names changed after a Home Assistant update. Does that mean this flow no longer works?
Not necessarily. The official English interface renamed Add-ons to Apps, and translations and button positions can move between versions. Navigate by what each step is for — Settings → Apps → Apps store → Repositories — and follow the latest official Home Assistant documentation.
