第 8 章

設定 external hostname

把 Home Assistant 接到一個清楚的公開 hostname，還要讓 Home Assistant 只信任正確的反向代理。你會完成附加元件與 http 設定，並用內外網兩條路徑驗收。

有網址還不等於能安全登入

external_hostname 告訴本機管理型 Cloudflared 附加元件：哪個公開網域名稱要送到 Home Assistant。但 Tunnel 前方有反向代理，Home Assistant 預設會阻擋未被信任代理送來的要求，所以還必須正確設定 use_x_forwarded_for 與 trusted_proxies。

兩次不同的重啟：修改 configuration.yaml 後要重新啟動 Home Assistant；在 Config 按 Save & Restart 則會改寫 Supervisor options 並重新啟動 Cloudflared Web GUI 附加元件。兩者都可能暫時中斷連線，請先保留可用的本機入口。
本教程沒有動到示範環境：內容來自唯讀觀察與文件查證，沒有在截圖用 Home Assistant 儲存設定、重啟、授權或建立 DNS。以下步驟只有你在自己的系統執行時才會產生變更。

先看懂 hostname 與代理路徑

位置扮演角色你要設定什麼
Cloudflare DNS 與 edge接收瀏覽器對公開 hostname 的 HTTPS 連線網域必須使用 Cloudflare DNS；本機管理型流程會建立對應 Tunnel DNS 路由
Cloudflare Tunnel從家中向外連到 Cloudflare，不需在路由器開入站連接埠在附加元件填 external_hostname
Cloudflared 附加元件把符合 hostname 的要求送往 Home Assistant正常運作並有 edge connection
Home Assistant HTTP判斷代理轉送的原始用戶端資訊是否可信啟用 forwarded headers，且只信任附加元件 Docker 網段

依附加元件 DOCS，Home Assistant OS／Supervisor 的標準附加元件網路使用下列可信任代理網段。它是網段，不是 Cloudflare 公開 IP 清單：

http:
  use_x_forwarded_for: true
  trusted_proxies:
    - 172.30.33.0/24
不要放寬成所有來源：Home Assistant 官方 HTTP 文件提醒，只有直接連到 Home Assistant 的反向代理才應列為 trusted proxy。過度寬廣的範圍會讓不可信來源有機會偽造轉送資訊。

從備份到外網驗收

  1. 先確認模式與網域

    這一章的 external_hostname 適用本機管理型 Tunnel。若 Config 已填 tunnel_token，其他 options 會被忽略，請改到 Cloudflare Zero Trust 設 public hostname。使用本機模式時，確認目標網域已交由你的 Cloudflare 帳號管理。

  2. 選一個專用 hostname

    例如你自己的 ha.example.com。Config 欄位只填 hostname，不要加 https://、連接埠、路徑或結尾斜線，也不要照抄範例網域。

  3. 備份 configuration.yaml

    在修改前建立 Home Assistant 備份，或至少保留該檔案目前可還原的副本。確認你能透過家中網路的本機網址操作；只有遠端 Tunnel 可用時，不要冒險重啟。

  4. 在既有 http 區塊合併代理設定

    使用你信任的檔案編輯方式開啟 /config/configuration.yaml。若已經有頂層 http:，把兩個鍵合併進同一區塊，不能再建立第二個 http:。標準附加元件安裝使用上方文件指定的 172.30.33.0/24。

  5. 先檢查 YAML 再重啟 Home Assistant

    YAML 以空白縮排，不要用 Tab。使用你目前 Home Assistant 版本提供的設定檢查功能確認語法；介面路徑可能改版，找不到時依官方 configuration 文件操作。檢查通過後才完整重新啟動 Home Assistant。

  6. 確認本機登入仍正常

    等待 Home Assistant 完成啟動，用原本本機網址登入並看系統日誌是否出現 HTTP 設定錯誤。若啟動失敗，先還原剛才的 YAML，不要繼續動 Tunnel。

  7. 在 Config 填入 external_hostname

    開啟 Cloudflared Web GUI → Config，把選好的名稱填入 external_hostname。重新核對拼字、網域與模式；第一次建立本機管理型 Tunnel 時，後續可能需要依 Setup／Logs 顯示的流程完成 Cloudflare 授權。

  8. 接受影響後按 Save & Restart

    這一步會真的寫入 Supervisor options 並重新啟動附加元件，Tunnel 會短暫中斷。等 Dashboard 恢復並確認有 edge connection，再查看 Logs 是否完成 DNS route 與連線流程。

  9. 用行動網路測試完整網址

    手機關閉 Wi-Fi，以 https://你的-hostname 開啟。確認憑證正常、登入頁出現、登入後操作與即時畫面持續更新。不要只在家中 Wi-Fi 測，否則無法證明外部路徑可用。

授權資訊不可外傳：Cloudflare 授權網址是用來連結帳號與網域的敏感流程；token、憑證與包含秘密的 log 也不可貼到聊天、論壇或 issue。若需要求助，只提供遮蔽後的錯誤片段。

對外前逐項確認

  1. 路由器沒有新增入站轉送

    Cloudflare Tunnel 是由家中主動向外連線，不需要把 8123 或其他服務連接埠轉送到網際網路。若過去曾開埠，確認沒有其他用途後再依你的路由器程序移除。

  2. trusted_proxies 維持最小範圍

    標準附加元件照 DOCS 使用 172.30.33.0/24；非標準環境以日誌與實際拓樸判斷。不要信任所有 IPv4、整個家用 LAN，或不會直接連到 HA 的 Cloudflare edge 範圍。

  3. Home Assistant 帳號有防護

    每位使用者使用自己的帳號與強密碼，管理者啟用多因素驗證。Tunnel 不會讓弱密碼自動變安全，也不能取代 Home Assistant 權限控管。

  4. 公開名稱不洩漏更多資訊

    hostname 雖不是密碼，仍避免放入住址、姓名或設備型號。分享畫面與 Logs 前遮蔽完整 hostname、IP、帳號、Tunnel ID、token 與授權網址。

  5. Cloudflare 額外保護有明確規劃

    需要更嚴格限制時，可另行評估 Cloudflare Access；但先確認 Home Assistant App、webhook 與其他整合的相容性。Access 是另一層政策，不取代 Home Assistant 登入。

External hostname 常見卡關

  1. 瀏覽器顯示 400 或 HA 日誌說代理不受信任

    確認 use_x_forwarded_for: true 與 trusted_proxies 在同一個頂層 http: 內，YAML 縮排正確，且修改後已完整重啟 Home Assistant。非標準部署依日誌找直接代理位址，別直接放寬成所有來源。

  2. 出現 502 Bad Gateway

    這通常表示 Cloudflared 到 origin 的連線不成功。先確認 Home Assistant 本機可用，再檢查是否自訂 HTTP port 或 SSL；若有，完整 http: 區塊應直接存在 configuration.yaml，讓附加元件能偵測。

  3. hostname 找不到或開到舊服務

    核對拼字、Cloudflare 帳號中的 DNS zone 與 Logs。附加元件啟動本機管理路由時可能改寫匹配的既有 DNS 記錄，因此不要拿已供其他服務使用的 hostname 測試；必要時先回復原 DNS。

  4. Tunnel connected，但 external_hostname 不生效

    檢查 Config 是否有 tunnel_token。有 token 代表遠端管理型模式，本機 options 會被忽略；請到 Cloudflare Zero Trust 核對 public hostname 與 origin service。

  5. 登入後頁面反覆斷線或功能不即時

    先確認 Cloudflare 網域的 WebSockets 可用，再看瀏覽器與 HA／附加元件日誌中的同一時間點。不要先關閉所有安全設定；一次改一項並重測。

常見問題

external_hostname 要填完整的 https 網址嗎？
不要。只填 hostname，例如 ha.example.com，不含 https://、port、路徑或斜線。瀏覽器驗收時才使用完整的 https://ha.example.com。
為什麼一定要設定 trusted_proxies？
要求先經 Cloudflare 與 Cloudflared 代理才到 Home Assistant。Home Assistant 預設不接受未被信任代理送來的 forwarded headers；必須明確信任直接代理，才能安全處理原始用戶端資訊。
可以把 trusted_proxies 設成所有 IP，先求能用嗎？
不可以。這會破壞信任邊界。標準附加元件依 DOCS 使用 172.30.33.0/24；非標準環境看 HA 日誌與網路拓樸，只加入必要的直接代理 IP 或最小網段。
改 configuration.yaml 後，只重啟附加元件可以嗎？
不行。這是 Home Assistant 的 HTTP 設定，要在檢查 YAML 後重新啟動 Home Assistant。修改 Config 並按 Save & Restart 則是另一件事，會重啟 Cloudflared 附加元件。
一定要把 Home Assistant 公開，才能使用 Tunnel 嗎？
不用。依附加元件 DOCS，external_hostname 可留空，只使用 additional_hosts。反過來，如果只需要 Home Assistant，也不要順手新增其他內網服務。
