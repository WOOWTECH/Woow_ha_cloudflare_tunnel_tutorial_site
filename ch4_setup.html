第 4 章

Setup 精靈：先選管理模式

先分清楚本機管理與遠端管理，再看 Setup 精靈每一步代表什麼。你會完成設定計畫、知道何時會寫入與重啟，但不會把兩種模式混在一起。

Setup 是進度表，不是另一套設定

從第 3 章認完四個頁面後，最容易誤會的就是 Setup：它看起來像會替你收集所有資料的表單，其實主要負責觀察首次啟動進度。真正的值仍放在 Supervisor options，由 Config 與 Home Assistant App 設定頁讀寫；Tunnel 的登入、建立、DNS route 與連線工作，則在 App 啟動時依那些值自動執行。

開始前先選管理模式很重要。本機管理型（local-managed）由 App 建立 Tunnel、保存本機憑證並依 options 建立路由；遠端管理型（remote-managed）由 Cloudflare 儀表板管理，App 只使用 tunnel_token 連線。若像把兩份住址同時交給宅配員一樣混搭，畫面雖然還看得到 hostname 欄位，實際上卻可能完全不採用它。

操作邊界：本教學的擷取環境只讀 Setup，沒有儲存、重新啟動、進行 Cloudflare 授權、建立 Tunnel 或變更 DNS。以下正式操作只適用於你自己控制、已備妥本機退路的 Home Assistant。
先記住：Save & Restart 會修改 Supervisor options，接著重新啟動 App；它不是預覽或下一步按鈕。重啟會讓 Web GUI 與 Tunnel 暫時中斷，也可能觸發授權、Tunnel 建立與 DNS route。

七步完成 Setup 前置規劃

  1. 先確認本機退路與維護時段

    用家中 Wi-Fi 開啟 Home Assistant 本機網址並登入，確認不是只靠目前 Tunnel。若人在外面、家中沒有人可協助，或目前連線正被家人使用，就停在規劃，不做任何重啟。

  2. 確認 Cloudflare 帳號與 DNS zone

    登入你自己的 Cloudflare 帳號，確認預定網域確實使用 Cloudflare DNS，且你有管理正確 zone 的權限。預定 hostname 若已有網站、郵件或其他用途，另選新名稱，因本機流程可能覆寫相符 DNS 記錄。

  3. 只選一種模式

    沒有既有 remote-managed Tunnel 時，依專案 DOCS 選本機管理型。若已在 Cloudflare 建立 Tunnel、知道 public hostname 在哪裡維護，而且持有該 Tunnel token，才選遠端管理型；把選擇寫在非敏感維護筆記。

  4. 完成 Home Assistant 反向代理設定

    若要把 Home Assistant 放在 Tunnel 後方，先在本機備份 configuration.yaml，再依專案 DOCS 將下列最小設定合併到既有 http: 區塊。標準 Supervisor App 情境使用文件指定的 Docker 網段；非標準安裝不要照抄，應依實際 HA 日誌判斷。

    http:
  use_x_forwarded_for: true
  trusted_proxies:
    - 172.30.33.0/24

    用 Home Assistant 的設定檢查確認 YAML 正常，安排一次 HA 重新啟動，並重新驗證本機網址可登入。這一步是正式變更；若沒有本機退路就停下來。

  5. 在 Config 填入最小本機路由

    本機模式第一次只填一個真正屬於你的 external_hostname，例如 ha.example.com；確認它位於正確 Cloudflare zone，且沒有承載網站、郵件或其他既有服務。保持 additional_hosts 為空，不啟用 catch-all、萬用 DNS、路由器或 NAS 管理頁。

  6. 遠端模式只準備 token 與 Cloudflare 路由

    在 Cloudflare 儀表板建立的 Tunnel 取得 token，使用密碼管理器保管；public hostname 與 origin service 也在 Cloudflare 端設定。不要同時期待 App 的 local options 管理相同路由。

  7. 回 Setup 核對預期路線

    本機模式在 Config 填完最小值後，先不要按按鈕，回頭確認 Setup 預期顯示 Configure、Authorize、Tunnel created、Tunnel connected 四步；遠端模式應顯示 token 提示。接著回 Config 做最後核對。只有你在自己的環境、已完成 HA proxy 設定、有本機退路與維護時段時，才可按 Save & Restart；它會真實寫入 options 並重啟 App，然後本機模式才進入第 5 章授權。

最小變更原則：第一次只讓一個必要 hostname 通過。完成授權與端到端測試後，再依第 9 章評估 additional hosts。

進入正式變更前的安全停止線

  1. 祕密只留在可信裝置

    授權網址、tunnel_token、cert.pem、Tunnel UUID、登入 cookie 與完整 Logs 都不可貼到社群、issue、共用筆記或未遮罩截圖。一般設定筆記只記模式與非敏感 hostname。

  2. 不要公開 Web GUI

    Web GUI 經 Home Assistant Ingress 與登入保護使用，不必對外映射內部 8099。Tunnel 的 public hostname 應指向預定服務，不是 Cloudflared 管理頁。

  3. 確認 DNS 不會誤傷現有服務

    本機模式啟動可能覆寫與 external hostname 或 additional hosts 相符的 Cloudflare DNS 記錄。逐筆確認名稱空閒，不要拿公司網站、郵件或家人正在使用的名稱測試。

  4. 限制公開範圍

    只建立有明確擁有者與用途的 hostname，不開 catch-all 或萬用 DNS 當捷徑。Tunnel 不會自動替 origin 修補漏洞，也不取代 Home Assistant 強密碼與多因素驗證。

  5. 理解兩個重啟入口

    Config 的 Save & Restart 會先修改 Supervisor options 再重啟；Dashboard 的 Restart Add-on 會用已儲存值重跑 setup。兩者都會中斷，規劃與唯讀檢查都不需要按。

擷取環境禁止事項：不要為了取得完成畫面，在指定擷取環境按 Save、Save & Restart、Restart Add-on、授權連結或 Copy link。需要示範的狀態以文字與表格說明，不製造真實憑證或 DNS 變更。

Setup 常見卡關

  1. 空白設定卻顯示 Tunnel stopped

    這是此 fork 的預期首次狀態，不是 App 安裝壞掉。只要 Ingress 與四頁可開，就先規劃真正設定；不要用假 hostname 或 token 消除紅色狀態。

  2. 填了 hostname，Configure 仍未完成

    先重新讀取 Config，確認值真的已寫入 Supervisor options。只在表單輸入但未儲存不算；若按 Save & Restart，則它已造成修改與重啟，應等待 App 回來而不是再次按。

  3. 本機四步突然被 token 提示取代

    表示目前 options 有 tunnel_token。不要直接清除或貼上另一個 token；先確認這是不是既有 remote-managed Tunnel，並和管理者核對 Cloudflare 端路由。

  4. 一直 Waiting for authorization

    確認本機模式已有完整必要設定且 App 完成重啟，再看 Logs 是否出現登入要求。授權網址沒出現時不要自己拼網址；依第 5 章檢查網路、時間與第一個 prepare 錯誤。

  5. Certificate found，但 Tunnel 沒建立

    憑證存在只完成第二步。查看 Logs 中授權後第一個明確錯誤，確認 Tunnel 名稱在帳號內唯一、Cloudflare 權限與網路可用；不要刪憑證或反覆授權當第一招。

  6. Setup 顯示 prepare failed

    先記下發生時間，到 Logs 擷取最小且已遮罩的錯誤上下文。修正明確設定問題後才安排一次重啟；連續重啟只會增加雜訊，也可能重複碰 DNS。

Setup 常見問題

Setup 會把資料存在另一份設定嗎？
不會。Supervisor options 是單一事實來源；Setup 主要觀察模式、憑證、Tunnel 檔案與連線進度，Config 才是 Web GUI 內的 options 編輯入口。
第一次使用該選本機還是遠端管理？
專案 DOCS 將本機管理列為建議流程。已熟悉 Cloudflare Zero Trust、已有 remote-managed Tunnel 並清楚 token 與 public hostname 責任時，才選遠端管理。
遠端管理模式還要完成 Setup 四步嗎？
不用。設定 tunnel_token 後，Setup 會說明本機四步不適用；Tunnel 與 routes 在 Cloudflare 儀表板管理，App 內其他 local options 會被忽略。
可以先填 hostname，之後再決定模式嗎？
可以先離線規劃，但不要急著儲存。模式會決定那些欄位由誰採用；先選定責任邊界，再做一次小而完整的變更，比事後混搭安全。
Save & Restart 只是讓 Setup 重新整理嗎？
不是。它會修改 Supervisor options 並重新啟動 App，Web GUI 與 Tunnel 會暫時中斷；本機模式還可能接著要求授權、建立 Tunnel 與 DNS route。
為什麼擷取環境沒有完成畫面？
因為完成畫面需要真實儲存、重啟、Cloudflare 授權或 Tunnel 狀態。本站依安全邊界不在擷取環境做這些變更，改以目前專案文件與原始碼說明。
