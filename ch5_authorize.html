第 5 章

Cloudflare 一次性授權

本機管理模式第一次啟動時，Setup 會顯示敏感的 Cloudflare 授權連結。你會知道如何在自己的環境核對帳號與 zone、完成後如何驗收，以及為什麼不能把連結、憑證或畫面交給別人。

這不是普通登入連結

本機管理型 Tunnel 需要先執行 cloudflared tunnel login。Cloudflared 產生瀏覽器授權流程，讓你登入 Cloudflare 並選擇要授權的網域 zone；成功後會下載帳號憑證 cert.pem，App 才能接著建立 Tunnel 與 DNS route。Web GUI 的 Setup 只是把原本藏在 Logs 的連結顯示成可點選按鈕。

這個流程像把自家門鎖的配對權交給新鑰匙，不是閱讀一般公開網頁。授權網址、登入工作階段與產生的憑證都可能影響你的 Cloudflare 資源，不能轉貼給朋友「代按」、放進公開 issue，也不能為了截圖在不該變更的環境實際操作。

擷取環境聲明：本站指定擷取環境沒有按下授權連結、沒有登入 Cloudflare、沒有選擇 zone，也沒有建立 cert.pem、Tunnel 或 DNS route。完成狀態以官方文件與專案行為說明，不用真實授權換取畫面。
前一步已有真實影響：授權連結通常在本機設定完成並重新啟動後出現。Config 的 Save & Restart 會修改 Supervisor options 並重啟 App；不要把它當成只開啟授權頁的無害按鈕。

授權連結、zone、憑證各自做什麼

項目角色安全界線
Setup 授權連結把瀏覽器帶進 cloudflared tunnel login 流程；只在尚無本機憑證且 App 等待時顯示視為一次性敏感流程資料，不貼出完整 URL、不截圖、不傳訊息
Cloudflare 帳號決定你能看到哪些 DNS zones 與 Tunnel 資源逐字核對帳號與登入身分；使用帳號本身的多因素驗證
zone／hostnameCloudflare 授權頁要求你選擇的網域；必須和本次預定公開名稱相符只選預定 hostname 所屬 zone，不因名稱相似選錯公司或客戶網域
cert.pemCloudflared 本機管理 Tunnel 使用的帳號憑證，可用來管理該帳號的 Tunnels不是網站 TLS 憑證；權限不只是一張成功畫面，絕不可公開、下載到共用位置或貼進求助內容
Tunnel 憑證檔授權後建立 Tunnel 時產生，對應特定 TunnelTunnel UUID 與檔案內容都應遮罩並限制存取
tunnel_token遠端管理型 Tunnel 的 connector token另一種模式的祕密；設定 token 時本章 local 授權不適用
「一次性」的正確理解：把 Setup 當作只在需要首次本機授權時使用的一次流程，不要把網址當永久書籤。成功後 Setup 以偵測到 cert.pem 判定授權完成，便不再顯示該登入網址。
授權不等於公開成功：看到 Certificate found 只證明本機憑證存在；還要等待 Tunnel 建立、edge connection、DNS 與 Home Assistant proxy 設定通過，不能跳過後續驗收。

在自己的環境安全完成授權

  1. 確認模式、退路與變更時段

    先完成第 4 章：Dashboard Mode 應是 local，沒有 tunnel_token；家中 Wi-Fi 的 Home Assistant 本機網址可登入。若你只剩 Tunnel 遠端入口，先不要繼續。

  2. 核對已儲存的最小設定

    確認預定 external hostname 或必要 additional host 屬於你控制的 Cloudflare zone，且沒有覆寫既有重要 DNS。若尚未儲存，安排維護時段後才從 Config 使用 Save & Restart；它會寫入 Supervisor options 並重新啟動 App。

  3. 在 Setup 等待連結出現

    重啟後回到 Setup，等待 Authorize with Cloudflare 顯示 Open Cloudflare authorization page。不要自己從 Logs 拼接網址，也不要按 Copy link 再經聊天、電子郵件或雲端剪貼簿轉傳。

  4. 在同一台可信裝置直接開啟

    選 Open Cloudflare authorization page，讓瀏覽器在新分頁開啟。核對網址列確實是 Cloudflare 官方網域，使用你自己的密碼管理器與多因素驗證登入；若導向陌生網域或憑證警告，立即關閉。

  5. 逐字核對帳號與 zone

    確認目前登入的是預定 Cloudflare 帳號，從授權頁選擇預定 hostname 所屬的正確 zone。若同時管理家庭、公司或客戶網域，別只看相似名稱；無法確認就取消，不要用「先選一個試試看」。

  6. 選對網域並回到 Setup

    依 Cloudflare 畫面選擇預定 hostname 所屬網域並完成授權後，不要截取成功頁或保留授權 URL。這會產生可管理帳號 Tunnels 的帳號憑證，不應誤認為只對單一頁面有效。回到 Web GUI；App 應自動繼續，Setup 由等待變成 Certificate found，接著建立 Tunnel、建立 DNS route 並嘗試連線。

  7. 等待自動流程，不重複授權

    Setup 會自行更新。先等 Tunnel created 與 connected，再到 Logs 看第一個明確結果；不要因幾秒內未變綠就重新開連結、再次授權、重新整理 Cloudflare 成功頁或連續重啟。

  8. 做端到端與隱私驗收

    依本章測試表確認憑證、Tunnel、edge connection、DNS 與外部 HTTPS；同時確認沒有把授權網址、zone 清單、帳號、Tunnel UUID、IP 或完整 Logs 留在截圖、下載資料或共用剪貼簿。

安全的協助方式：若家人需要技術協助，由帳號擁有者在可信裝置親自登入與按授權。協助者只看已遮罩畫面或必要錯誤摘要，不接收連結、密碼、MFA 碼或憑證。

授權資料的保護與外洩處理

  1. 驗證官方網域與 TLS

    只從 Setup 直接開啟連結，確認瀏覽器顯示 Cloudflare 官方 HTTPS 網域且無憑證警告。不使用搜尋廣告、短網址或陌生人傳來的登入頁。

  2. Cloudflare 帳號啟用 MFA

    授權會碰到 DNS 與 Tunnel 管理能力，帳號應使用獨立強密碼與多因素驗證。MFA 備援碼同樣不能放在公開筆記或傳給協助者。

  3. 縮小可見與可分享內容

    不拍攝授權頁、zone 清單、帳號選單、完整 Logs 或 Setup URL。求助只描述「連結未出現」或貼已遮罩、最小範圍的第一個錯誤。

  4. 保護本機資料目錄

    cert.pem 與 Tunnel 憑證由 App 使用，不需要下載到日常電腦、NAS 共用資料夾或版本庫。Home Assistant 備份也含敏感設定，應加密並限制存取。

  5. 懷疑外洩就停止流程

    若 URL、登入 cookie、token 或憑證曾被貼出，先中止授權與公開變更，從 Cloudflare 與 Home Assistant 登出可疑工作階段，檢查 Tunnel、DNS 與帳號活動，再依官方機制撤銷或輪替相關憑證。

  6. 不要用刪訊息取代撤銷

    聊天訊息、issue 或錄影可能已有副本。刪除公開內容只能降低持續曝光，不能證明祕密未被讀取；必須把它視為已外洩並做帳號與憑證處理。

絕不分享：授權網址、Cloudflare 密碼、MFA 碼、cert.pem、Tunnel token、Tunnel 憑證、登入 cookie 與未遮罩日誌。即使對方自稱官方客服，也不要透過聊天提供。

Edge 連線看 Setup connected 與 DashboardTunnel running，ready edge connections 大於 0
DNS在 Cloudflare DNS 核對預定 hostname只變更預定名稱，沒有覆寫其他網站或郵件記錄
本機 HA家中 Wi-Fi 使用本機網址仍可登入與操作，保留不依賴 Tunnel 的退路
外部 HTTPS手機關閉 Wi-Fi，以行動網路開預定完整網址到正確 Home Assistant 登入頁，HTTPS 正常且頁面可持續更新

Cloudflare 授權常見卡關

  1. 授權按鈕一直不出現

    先確認 Dashboard 是 local，Setup 不是未設定狀態，而且 App 已依完整設定啟動。查看 Logs 的第一個 prepare 錯誤；不要自行產生網址、清除憑證或反覆按 Restart。

  2. 連結開啟後過期、無效或停在錯誤頁

    關閉舊頁，不要把 URL 貼到別台裝置測試。回 Setup 看流程是否仍等待，核對主機時間、DNS 與外網連線；若需重新產生，先依 Logs 判斷原因，再於維護時段做單次重啟。

  3. 登入後看不到預定 zone

    最常見是登入錯帳號、網域未使用該帳號的 Cloudflare DNS，或目前身分沒有足夠權限。取消授權並回 Cloudflare 帳號頁核對；不要選相似但不屬於本次用途的 zone。

  4. 已授權，Setup 還是等待

    先等待頁面下一次自動更新，再看 Logs 是否成功寫入憑證或收到權限錯誤。不要重送成功頁；若 cert.pem 未建立，保留已遮罩的第一個錯誤供排查。

  5. Certificate found，但 Tunnel 建立失敗

    授權已過，不必先重做。檢查 Tunnel 名稱是否在同一 Cloudflare 帳號內唯一、API 連線與權限錯誤；只修正明確問題後重試一次。

  6. Tunnel 建立了但 hostname 不通

    移到 Dashboard、Cloudflare DNS、Home Assistant HTTP proxy 與 origin 層排查。確認 edge connections、DNS 只指向預定 Tunnel，以及 trusted_proxies 依官方文件設定；不要再次授權。

  7. 不小心分享了授權網址或畫面

    立即停止流程，刪除公開內容但不要以為這就完成；登出可疑工作階段，檢查 Cloudflare 帳號、Tunnel 與 DNS 活動，依官方方式撤銷或輪替可能受影響的憑證，並更換已外洩的 token。

授權常見問題

遠端管理型 Tunnel 也要開這個授權連結嗎？
不用。遠端模式使用 Cloudflare 儀表板提供的 tunnel_token；Setup 會顯示 token 模式提示，本機管理的授權、憑證與四步流程不適用。
可以把連結複製到手機完成嗎？
不建議經聊天、郵件或跨裝置剪貼簿傳送。最安全做法是在顯示 Setup 的同一台可信裝置直接開啟；若裝置不可信，就先停止而不是搬運敏感 URL。
授權後產生的是網站 HTTPS 憑證嗎？
不是。cert.pem 是 cloudflared 本機管理 Tunnel 使用的帳號憑證，不是瀏覽器看到的網站 TLS 憑證；仍要當作祕密保護。
看到 Certificate found 就能從外面登入了嗎？
不一定。還要完成 Tunnel 建立、DNS route、edge connection、Home Assistant proxy 設定與外部 HTTPS 測試；依本章驗收表逐層確認。
授權時選錯 zone，可以繼續再改嗎？
不要繼續建立路由。停止流程，先檢查 Cloudflare 帳號與任何已產生資源，再依官方方式撤銷錯誤授權或憑證；確認乾淨後才用正確 zone 重做。
為什麼教學不提供授權成功截圖？
因為授權頁會顯示帳號、zone 與敏感流程資訊，而且取得完成狀態需要真實變更。本站明確不在擷取環境授權，使用文字與官方來源說明。
