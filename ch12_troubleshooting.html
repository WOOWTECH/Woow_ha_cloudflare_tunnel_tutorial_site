第 12 章

排錯、更新與交接

從手機看到的結果一路往內查到 DNS、Cloudflare edge、Tunnel connector、cloudflared 與 Home Assistant origin。你也會學會在更新前留退路、失敗時安全回復，並交出不含祕密但足以接手的紀錄。

為什麼要學這個

遠端網址打不開時，最常見的錯誤不是「整套都壞了」，而是其中一層沒有接上。若一開始就重裝 add-on、改 DNS、重設 token，等於家裡跳電時先拆配電箱：不但證據消失，還可能新增第二個問題。

本章採用由外往內（outside-in）的順序：先保存使用者實際看到的錯誤，再確認 hostname 與 Cloudflare edge，接著看 Tunnel connector、add-on 日誌，最後驗證 Home Assistant 本地 origin。每一步只有一個判斷，找到第一個失敗層就停在那層處理。

排錯三件套：記下發生時間、完整錯誤碼或畫面文字、當時使用 Wi-Fi 還是行動網路。不要只寫「不能用」，也不要把授權網址、token 或整份未遮密日誌附上。

先讀懂外部症狀

外部看到的結果優先懷疑的層下一個唯讀檢查
hostname 找不到／DNS 錯誤拼字、DNS 記錄或尚未傳播／快取。到 Cloudflare DNS 核對完整 hostname 與記錄，不要先重啟 add-on。
Cloudflare Error 1033Cloudflare 找不到可用的 Tunnel connector。看 Cloudflare Tunnel connector 狀態、Web GUI Dashboard 與 add-on Logs。
Cloudflare 502請求到達 Cloudflare／connector，但 cloudflared 無法正確連到設定的 origin 是常見方向。先測 HA 本地網址，再查 origin URL、port、TLS 與 proxy 錯誤。
Cloudflare Access 拒絕或登入循環Access application、policy、身分提供者或瀏覽器 session。用允許帳號與私人視窗測一次，核對 application hostname 與 policy。
Home Assistant 反向代理錯誤trusted_proxies 或 use_x_forwarded_for。查 HA 日誌中的實際來源，再依 HTTP 官方文件核對，不要放寬成信任全網。
能到 HA 登入但功能異常Tunnel 基本路徑已通，問題較靠近 HA 帳號、前端、整合或 WebSocket。比較本地與外部結果，保留瀏覽器與 HA 日誌的同一時間點。
狀態不是結論：Dashboard 有 edge connection 只表示 connector 與 Cloudflare edge 有連線；它不能證明 DNS 指對、Access policy 正確，也不能證明 origin Home Assistant 可用。

由外往內排一次

  1. 固定測試條件並保存症狀

    手機關閉 Wi-Fi，以行動網路開啟完整 https://hostname。只測一次，記下時間、錯誤碼與是否到達 Cloudflare Access 或 HA 登入。若頁面含識別資訊，請用文字記錄，不必截圖。

  2. 核對 hostname 與 DNS

    確認網址沒有拼字、額外空格或錯誤子網域。到你自己的 Cloudflare DNS 唯讀核對該記錄是否存在且指向預期 Tunnel。local-managed add-on 會管理對應 DNS；remote-managed 路由則以 Cloudflare Dashboard 為準。

  3. 判斷 Cloudflare edge 是否已接手

    若出現 Cloudflare 品牌錯誤頁，保存完整錯誤碼。1033 優先查 connector；502 優先查 origin 可達性。若是 Access 拒絕，先查身分 policy，不要改 Tunnel token。

  4. 查看 Tunnel 與 add-on 狀態

    在 Cloudflare Dashboard 查看對應 Tunnel connector，再到 Web GUI Dashboard 看 add-on 與 edge connections。local-managed 與 remote-managed 的管理位置不同，但都需要至少一個健康 connector 才能承接流量。

  5. 比對同時段 Logs

    開啟 Logs，先清空 Filter，找到步驟一的時間；再分別過濾 error、warn 或錯誤中的非敏感詞。先下載並遮密，再考慮重啟。Disconnected 只表示日誌串流斷開，不等於 Tunnel 結論。

  6. 最後檢查 Home Assistant origin

    回到家中網路開啟 HA 本地網址。若本地也失敗，先修 HA；若本地正常而外部 502，核對 add-on 偵測的 HA port／SSL、http: 設定與 trusted proxy。一次只改一項，改後從最外層重測。

本站沒有替教學環境做任何修復：製作期間只唯讀查看，沒有按 Save、Save & Restart、Restart、Authorize、Delete，也沒有改 DNS、Tunnel 或 HA。你按 Save & Restart 會真實寫入 Supervisor options 並重新啟動 add-on，現有遠端連線會短暫中斷；沒有本地入口、備份與維護時段時不要執行。

更新與回復怎麼選

情境更新前失敗時的保守回復
只改 add-on options保存遮密後的原值與正常驗收結果，確認本地 HA 可登入。把單一變更還原成已知正常值；Save 只儲存，Save & Restart 才套用並重啟。
更新 Cloudflared Web GUI add-on讀 add-on Changelog，建立包含 add-on 設定的 Home Assistant 備份，記錄目前版本。優先使用更新前建立、已驗證可用的 HA 備份還原。不要假設 add-on 商店一定提供一鍵降版。
更新 Home Assistant讀官方 release notes 與 breaking changes，建立備份，確認 Cloudflared add-on 相容資訊。依 Home Assistant 官方備份／還原流程處理，並預留本地操作與停機時間。
修改 DNS／public hostname記錄舊記錄、路由與 origin，但排除 token；先確認誰管理 local 或 remote tunnel。還原上一個明確記錄，等待 DNS 快取更新後再測；不要同時重建 Tunnel。
修改 Cloudflare Access policy保留可用的管理者與本地 HA 入口，用允許／拒絕測試案例記錄舊行為。恢復上一個最小可用 policy，而不是開放所有人；再做雙向身分驗收。
疑似 token 外洩這不是一般更新。在 Cloudflare 端輪替／撤銷，檢查 connectors、DNS 與帳號活動，再安全更新受保護欄位。
cloudflared 不在容器內自行更新：add-on 文件列出預設啟動參數含 no-autoupdate。版本更新應跟隨 add-on 發行與映像，不要進容器手動替換執行檔，否則下次重建也不可靠。
一次只變更一層：先做設定回復並驗收；若仍失敗，再考慮版本回復。DNS、Access、token 與 add-on 同時改，最後無法知道哪個動作有效。

安全交接包怎麼寫

交接的目標是讓下一位維護者知道「系統怎麼連、哪裡管理、如何驗收與回復」，不是把所有祕密裝進同一份文件。下面資料足以排大多數問題。

交接項目可以記錄禁止放入
範圍與負責人Home Assistant、Cloudflare 帳號與 DNS 各由哪個角色維護，以及緊急聯絡方式。共用帳號密碼、MFA seed、復原碼。
版本HA Core／OS／Supervisor 與 Cloudflared Web GUI add-on 版本、最後驗收日期。未遮密的系統完整診斷包。
通道模式local-managed 或 remote-managed、Tunnel 顯示名稱、hostname 的用途。tunnel_token、TunnelSecret、憑證檔內容、Cloudflare 授權網址。
路由摘要external hostname 與必要 additional host 的業務用途、origin 類型與擁有者。不必要的私有 IP、管理 port、內網拓樸與裝置密碼。
正常標準本地／外部測試步驟、預期登入流程、Dashboard 與 Logs 應看到的概略結果。可重播的 session、cookie 或未遮密登入截圖。
回復計畫備份日期與受控保存位置、上一個正常版本／設定摘要、誰有權核准還原。把備份解密金鑰和備份檔放在同一份公開文件。
已知問題發生時間、錯誤碼、已試步驟與遮密後日誌片段。整份原始 debug／trace 日誌。
傳遞祕密要分流：若接手人確實需要 token 或復原碼，請走組織核准的密碼管理器與最小存取權，不要夾在交接文件、電子郵件、聊天記錄或 issue。交接完成後撤除前任不再需要的權限。

更新或回復後的完整驗收

  1. 版本與設定一致

    確認實際 add-on 版本符合計畫，Config 只包含核准變更；local／remote-managed 模式沒有意外切換，remote token 欄位未出現在任何紀錄。

  2. 本地 HA 正常

    家中網路可以登入、載入儀表板並執行一個無風險的唯讀操作。HA 日誌沒有因 proxy 設定持續拒絕請求。

  3. connector 與 Logs 正常

    Dashboard 顯示 add-on 執行、Tunnel 有 edge connection；Logs 可連線，啟動後沒有 fatal/error 反覆循環。連線數可變動，不要求固定值。

  4. 外部入口正常

    手機行動網路可到預期的 Access 或 HA 登入，登入後基本頁面可用；沒有路由到錯誤的 additional host。

  5. 拒絕路徑正常

    不存在或已撤除的 hostname 不會因 wildcard／catch-all 顯示內網服務；若使用 Access，不允許的測試帳號確實被拒絕。

  6. 維護收尾正常

    臨時 debug 已還原、下載日誌已遮密、路由器沒有新增入站 port、更新前備份依保留政策存放，交接紀錄寫入日期與結果。

接受或回復：六項全過才結案。任何一項失敗，先保存證據，依變更計畫回復最後一個動作，再完整重跑；不要把「大部分能用」當作完成。

常見故障的處理順序

  1. Error 1033：找不到健康 Tunnel connector

    先看 Cloudflare Tunnel connectors，再看 Web GUI Dashboard 與 add-on Logs。確認 add-on 是否啟動、家中網路能否向外連線。先保存日誌；有本地入口與核准時才做單次 restart，不要重建 DNS 或另建同名 Tunnel。

  2. Cloudflare 502：connector 到不了 origin

    先以家中網路測 HA 本地網址。若本地失敗，修 HA；若本地正常，核對 origin 的協定、port、HA SSL 與 http: 設定。從同時段 cloudflared／HA 日誌找 connection refused、TLS 或 proxy 線索。

  3. 外部正常但 Web GUI Logs 顯示 Disconnected

    這通常是 Ingress 頁面的日誌 WebSocket 問題，不代表 Tunnel 已斷。按 Connect 或重新整理頁面，確認 HA session 有效；仍失敗時改看 Home Assistant add-on Log，並保留瀏覽器發生時間。

  4. 更新後 add-on 起不來或行為改變

    記錄新舊版本與第一個錯誤，讀 add-on Changelog，確認 options schema 沒有不相容。不要立刻清資料或重裝；若符合回復條件，使用更新前 HA 備份還原，再驗收。

  5. 回復後仍看到舊 DNS 結果

    DNS 與本機／電信商快取不一定立即更新。先在 Cloudflare Dashboard 確認權威記錄正確，再等待合理快取時間並換另一個網路測試。不要因單一裝置舊快取反覆改記錄。

  6. 交接人只有遠端連線，改錯後失聯

    停止繼續嘗試。請有本地網路與授權的聯絡人依交接包登入 HA，先確認本地狀態與最後一個變更，再按核准回復計畫處理。這正是更新前要驗證本地入口與負責人的原因。

不要在公開求助中貼祕密：提供版本、時間、錯誤碼、模式、已試步驟和遮密片段即可。授權網址、token、Tunnel ID、帳號、hostname、IP 與完整日誌必須移除；若已貼出，應視內容立即撤銷或輪替。

常見問題

故障時第一步可以按 Restart 嗎？
不建議。先記時間、錯誤碼，下載並遮密日誌，再確認是哪一層。Restart 會中斷通道，也可能讓關鍵上下文離開畫面；只有已知暫時性 connector 問題、具本地回復入口且已核准時才做一次。
Save 與 Save & Restart 有什麼不同？
依 Web GUI 介面說明，Save 透過 Supervisor 寫入 options，但設定通常要重啟才生效；Save & Restart 會儲存後重新啟動 add-on，GUI 會短暫中斷。兩者都不是唯讀操作，執行前要確認差異與備份。
更新 add-on 會同時更新 cloudflared 嗎？
cloudflared 版本由 add-on 映像提供；文件列出的預設執行參數包含 no-autoupdate，所以不應期待容器內自行更新。請跟隨 add-on 發行、Changelog 與 Home Assistant add-on 更新流程。
可以只備份 YAML 文字當作完整回復嗎？
不夠。設定摘要有助於人工還原，但 add-on 版本、受保護資料與 Home Assistant 狀態不一定都在一段 YAML。重大更新前應使用 HA 官方備份功能，並確認備份包含需要的 add-on 資料；Cloudflare DNS／Access 變更還要另有遮密變更紀錄。
求助時最少要提供什麼？
提供 HA 與 add-on 版本、local 或 remote-managed、故障時間、外部完整錯誤碼、本地是否正常、Dashboard 概略狀態、已試步驟及少量遮密日誌。不要提供 token、授權網址、secret、完整 hostname、Tunnel ID、IP 或未遮密附件。
