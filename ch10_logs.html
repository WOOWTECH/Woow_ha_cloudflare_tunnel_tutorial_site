第 10 章

Logs 與日常維護

不用看懂每一行英文，也能從時間、嚴重程度與重複模式判斷通道是否健康。你會學會即時查看、過濾、下載與安全整理日誌，並建立不打擾家中服務的維護節奏。

為什麼要學這個

遠端連線出問題時，瀏覽器只會告訴你「打不開」，真正原因可能在 DNS、Cloudflare edge、cloudflared 或 Home Assistant。日誌就像玄關的出入紀錄：不用逐字背，只要先看故障發生的時間，再找同一時段反覆出現的警告或錯誤，就能把範圍縮小。

Cloudflared Web GUI 的 Logs 顯示 add-on 日誌的即時串流，內容來源與 Home Assistant add-on 的 Log 分頁相同，並提供文字過濾與下載。這一頁適合觀察與蒐證，不是永久稽核系統；重新開啟、清除畫面或緩衝區輪替後，舊行可能不再出現。

先記時間：請先記下「哪個網址、哪個裝置、約幾點幾分失敗」，再看該時段附近的日誌。這比從第一行讀到最後一行快很多。

先懂日誌的五個觀念

畫面或名詞它代表什麼你該怎麼用
Connected／Disconnected瀏覽器與 Web GUI 日誌串流是否連上，不等於 Tunnel 一定可用或故障。顯示 Disconnected 時先按 Connect 或重開頁面，再到 Dashboard 交叉確認通道。
Filter logs...在目前收到的行中做不分大小寫的文字包含比對；不會改寫原始 add-on 日誌。一次用一個短詞，如 error、warn、hostname 的非敏感片段。
Auto-scroll新行到達時自動捲到底部。追即時事件時開啟；閱讀較早內容時關閉，避免畫面跳走。
Clear清掉目前瀏覽器頁面累積的行；不代表刪除 Supervisor 或系統保存的歷史紀錄。重現問題前可清畫面，讓新事件更醒目；重要內容先下載。
Download把目前 Log Viewer 顯示的行下載成文字檔；介面版本不同時，檔名與按鈕文字可能略有差異。有開 Filter 時，現行 Web GUI 下載的是過濾後畫面；需要完整上下文就先清空 Filter。
兩種詳細程度：log_level 控制 add-on 自己的訊息；cloudflared 通道本體的詳細程度則由允許的 run_parameters（例如 --loglevel=debug）控制。兩者不是同一個開關。
顏色只是提示：Web GUI 會依文字中的 error、fatal、warn、debug 上色，仍要讀整行與前後文。單次 warning 不一定是故障；相同錯誤持續出現，才更值得追查。

完成一次安全的日誌檢查

  1. 先確認本機 Home Assistant 正常

    在家中網路開啟 Home Assistant 本機網址，確認能登入與操作。記下現在時間，另備一台關閉 Wi-Fi、使用行動網路的裝置，但先不要改任何設定。

  2. 開啟 Cloudflared 的 Logs 頁

    從 Home Assistant 側邊欄開啟 Cloudflared，再選 Logs。正常情況會自動連線；若狀態是 Disconnected，按 Connect。看到新行持續加入，只代表日誌串流正常，通道健康仍要另外驗收。

  3. 關閉自動捲動並定位時間

    取消 Auto-scroll，回到剛才記下的時間附近。先讀錯誤行的前後數行，辨認它是在準備設定、建立 edge 連線、設定 DNS，還是連往 Home Assistant origin 時出現。

  4. 逐次使用短詞過濾

    在 Filter 先輸入 error，再分別試 fatal、warn。不要把三個詞一次貼在一起，因為這裡是單一文字包含比對，不是進階查詢語法。需要看完整脈絡時清空 Filter。

  5. 從外部重現一次

    用行動網路開啟你的 external hostname，記下結果與時間。回到 Logs 查看同時段是否出現新錯誤，並到 Dashboard 對照 add-on 與 edge connection 狀態。測試一次即可，避免快速重複刷新造成雜訊。

  6. 下載前先決定要完整或精簡

    要交給維護者分析時，先清空 Filter 再按 Download，保留前後文；只想保留某類訊息時才維持 Filter。下載後先在文字編輯器檢查並遮掉 hostname、帳號、IP、Tunnel ID、授權網址、token 與其他內網資訊，再分享。

不要把操作示範誤認為已執行：本站教學環境製作期間只做唯讀查看，沒有按 Save、Save & Restart、Restart、Authorize 或變更 Tunnel。你在自己的 Config 按 Save & Restart，會真的寫入 Supervisor options 並重新啟動 add-on，短暫中斷通道；沒有維護時段與原設定備份時不要按。

日常維護怎麼安排

情境建議做法不要做的事
平常運作正常維持預設 info，每月或網路設備異動後做一次本地、外部與 Dashboard 快速驗收。長期開 debug 或 trace，累積不必要資訊與敏感上下文。
偶發斷線先記時間、下載未過濾日誌，再比對網路或 Cloudflare 狀態；讓證據先於重啟。一看到錯誤就連續重啟，洗掉發生順序。
需要更多 add-on 細節在維護時段暫時提高 log_level，重現一次後立即還原。誤以為它一定會增加 cloudflared 本體的訊息。
需要更多通道細節僅依 add-on 文件使用允許的 --loglevel=debug，先記錄原值，結束後移除或還原。貼入來源不明參數，或把完整命令列與 token 傳給他人。
準備更新 add-on先讀 add-on Changelog、建立 Home Assistant 備份、保存遮密後的設定摘要與正常驗收結果。遠端只剩這一條連線時直接更新，卻沒有本地復原方式。
最小維護紀錄：保留日期、Home Assistant 版本、add-on 版本、local-managed 或 remote-managed 模式、結果與已遮密的錯誤摘要即可。token 與 Cloudflare 授權網址永遠不屬於維護紀錄。

下載或分享前的安全檢查

檢查項目通過標準原因
授權資料沒有 Cloudflare 授權網址、tunnel_token、TunnelSecret、憑證內容或完整命令列。取得這些資料的人可能取得授權或讓連接器加入通道。
身分與位置遮掉帳號、電子郵件、hostname、公開與私有 IP、Tunnel ID、zone 或 account 識別資訊。降低針對住家入口與帳號的偵察風險。
內網服務遮掉 additional_hosts 的實際服務位址、裝置名稱與連接埠。這些資訊會畫出你的家庭網路地圖。
分享範圍只給負責排錯的人，使用有權限與到期管理的管道，問題結束後移除檔案。日誌不適合貼到公開討論區或搜尋得到的空間。
詳細等級日常維持 info；debug／trace 只在必要期間啟用並於驗收後還原。越詳細越可能帶出環境與執行細節。
Web GUI 有基本遮密仍不能取代人工檢查：專案會遮蔽已知的通道 token 與部分 secret 格式，但未知格式、hostname、IP 與業務內容仍可能出現。下載檔一律視為敏感資料。

維護完成後的驗收測試

  1. 本地入口通過

    同一個家中網路可以開啟 Home Assistant、登入並載入儀表板，確認 HA 本體不是故障來源。

  2. 外部入口通過

    手機關閉 Wi-Fi 後，以 https://你的-hostname 開啟；能到達預期的 Cloudflare 或 Home Assistant 登入流程，而且沒有路由到其他內網服務。

  3. Dashboard 通過

    Cloudflared Dashboard 顯示 add-on 在執行，Tunnel 有 edge connection；連線數會波動，不要把某個固定數字當成唯一標準。

  4. Logs 通過

    Logs 顯示 Connected，測試期間有新行，且沒有同一個 fatal/error 持續循環。短暫 warning 要搭配實際功能判斷。

  5. 安全狀態通過

    路由器仍未因本教學開放 Home Assistant 入站 port；臨時 debug／trace 已還原，下載檔已遮密並移到受控位置。

  6. 紀錄通過

    寫下測試日期、版本、模式與結果；不要記錄 token、授權網址或可直接使用的憑證。如果有變更，也記下復原方式。

驗收判斷：同時確認「實際能用、沒有送錯服務、沒有重複錯誤、沒有擴大暴露」。只看到綠色狀態不算完整驗收。

Logs 頁常見卡關

  1. 一直顯示 Disconnected

    先按 Connect，再重新整理 Cloudflared Ingress 頁。確認 Home Assistant 登入仍有效；若 Dashboard 也打不開，到 add-on 的 Home Assistant Log 分頁查看。Disconnected 描述的是日誌 WebSocket，不足以單獨判定 Tunnel 已斷。

  2. 過濾後完全空白

    清空 Filter，確認原始行仍存在，再改用較短的單一關鍵字。Filter 是不分大小寫的「包含」比對，不支援 AND、OR 或規則運算式；打錯一個字就可能沒有結果。

  3. 下載檔缺少想要的前後文

    目前介面會下載 Log Viewer 正在顯示的內容。若當時有 Filter，就可能只有符合的行；清空 Filter、重新重現一次再下載。過久的行也可能已離開記憶體緩衝，必要時交叉查看 HA add-on Log。

  4. 按 Clear 後以為系統紀錄被刪掉

    Clear 只清目前瀏覽器累積的訊息，新行仍會繼續到達；它不是清除 Supervisor 的日誌儲存。需要保留證據時，應在 Clear 或重啟之前先下載。

  5. 提高 log level 後看不出差異

    先分清 add-on 的 log_level 與 cloudflared 的 --loglevel。設定變更通常要重啟 add-on 才生效；按 Save 只寫入，按 Save & Restart 才會寫入並重啟。這是實際變更，請先備份、排維護時段並記錄原值。

先蒐證再重啟：Restart 會中斷目前通道，且可能讓最關鍵的啟動前上下文離開畫面。遠端管理時若沒有本地備援，請不要把重啟當作第一步。

常見問題

Logs 與 Home Assistant add-on 的 Log 分頁是兩套紀錄嗎？
不是。專案文件說明 Web GUI 串流的是 add-on 自己的日誌，內容與 HA Log 分頁相同；Web GUI 另外提供即時串流、過濾與下載的操作方式。兩邊顯示時間點或保留行數可能因頁面開啟狀態而不同。
看到紅色行就表示通道壞了嗎？
不一定。顏色是依行內文字做提示。先看該行時間、前後文、是否重複，再用外部入口與 Dashboard 驗證。單一舊錯誤不代表現在仍故障。
可以長期開 debug 方便日後排錯嗎？
不建議。詳細日誌會增加雜訊與敏感資訊暴露面。平常使用文件建議的 info；必要時短暫提高，重現一次、下載並遮密後還原。
可以把整份日誌貼到 GitHub issue 嗎？
不要直接貼。先複製一份、移除授權網址、token、secret、帳號、hostname、Tunnel ID、IP 與內網服務資料，只留下能重現問題的時間區段。若懷疑 token 已外洩，先在 Cloudflare 端輪替或撤銷，再處理公開內容。
Clear 和 Disconnect 會停止 add-on 嗎？
不會。Clear 清除瀏覽器目前累積的行；Disconnect 停止這個頁面的即時串流。它們都不是 Restart。通道狀態仍應到 Dashboard 與外部入口確認。
