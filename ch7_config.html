第 7 章

Config 與 Supervisor options

Config 不是另一份獨立設定，而是同一組附加元件選項的友善入口。你會先看懂目前值，再只改必要欄位，並在真正重啟前知道影響範圍。

先看懂再按儲存

你可能會在 Web GUI 的 Config 頁與 Home Assistant 的附加元件「設定」頁看到相同欄位。這不是兩套互相覆蓋的檔案：Cloudflared Web GUI 透過 Supervisor API 讀寫附加元件自己的 options，Supervisor options 才是唯一事實來源。從其中一邊存下的值，另一邊之後讀到的也會是同一組值。

操作影響：Config 的 Save & Restart 不是預覽。它會改寫 Supervisor options，接著重新啟動 Cloudflared Web GUI 附加元件；Tunnel 連線會短暫中斷。先確認家中有人可協助，並避開你只能靠這條 Tunnel 遠端管理的時段。
本教程的安全邊界：教學內容與截圖環境採唯讀觀察，沒有在該環境按下 Save & Restart、重新授權或變更 Tunnel。下面是你在自己的 Home Assistant 中操作時才會發生的變更。

Supervisor options 是單一來源

把 Supervisor options 想成家中配電箱上的正式標示，Config 與附加元件設定頁只是兩扇能讀寫同一張標示的門。看到兩邊內容不一致時，不要同時開兩個分頁輪流存檔；先重新整理，確認最後一次成功儲存的值。

入口實際作用適合情境
Web GUI → Config讀寫 Supervisor options，Save & Restart 後重啟附加元件一般使用者依欄位提示修改
Home Assistant 附加元件設定頁讀寫同一組 Supervisor options檢查實際儲存值或使用內建設定編輯器
Cloudflare Zero Trust管理遠端管理型 Tunnel 的公開主機名稱與路由使用 tunnel_token 的進階模式
configuration.yamlHome Assistant 本身的 HTTP 與可信任代理設定第 8 章的 trusted_proxies；不是附加元件 options
先判斷模式：本機管理型 Tunnel 由附加元件處理 hostname、DNS 與 ingress；遠端管理型 Tunnel 設定 tunnel_token 後，其他附加元件路由設定會被忽略，應到 Cloudflare 介面管理。

安全修改 Config 的完整流程

  1. 確認你仍有本機入口

    先用家中 Wi-Fi 開啟 Home Assistant 的本機網址，確認能登入。若你人在外面且唯一入口就是目前 Tunnel，先不要重啟；設定錯誤可能讓你無法連回家。

  2. 開啟 Cloudflared Web GUI 的 Config

    從附加元件頁的「開啟 Web UI」或已啟用的 Cloudflared 側邊欄進入，再選 Config。不同版本的按鈕大小或英文大小寫可能不同，以頁面中的 Config 為準。

  3. 辨認本機或遠端管理模式

    如果 tunnel_token 有值，視為遠端管理型 Tunnel，公開 hostname 與路由應在 Cloudflare Zero Trust 管理。若沒有 token，才依本章表格檢查 external_hostname、additional_hosts 等本機管理選項。

  4. 另存目前值並只改一類設定

    在自己的離線筆記記下非敏感欄位，例如 tunnel 名稱與 hostname；不要抄錄 token 或完整授權網址。一次只改一類，例如先改 log_level，不要同時改 hostname、代理與執行參數，日後才容易回復。

  5. 逐欄檢查格式

    hostname 只填網域名稱，不加 https://、路徑或結尾斜線。額外服務則需要完整的 origin service，例如 http://192.168.1.20:8080。不確定的進階欄位維持原值。

  6. 理解影響後才按 Save & Restart

    確認沒有其他人正在依賴遠端連線，再按 Save & Restart。這會把表單寫入 Supervisor options 並重新啟動附加元件，不是只儲存草稿。畫面暫時失去連線屬正常現象，請等待附加元件重新啟動。

  7. 重新讀取並查看 Logs

    回到 Config 重新整理，確認剛才修改的非敏感欄位仍存在；再到 Dashboard 與 Logs 確認附加元件有運作、Tunnel 有 edge 連線，且沒有持續重複的 fatal 或 error 訊息。

不可分享：tunnel_token、Cloudflare 授權網址、憑證內容，以及可能含 hostname、IP、帳號或 token 的完整 log 都是敏感資料。求助時只貼必要片段，先遮蔽秘密與可識別資訊。

每個選項該不該動

選項用途保守建議
external_hostname本機管理型 Tunnel 給 Home Assistant 使用的公開 hostname；可留空只填你已放在 Cloudflare DNS 區域中的網域名稱；第 8 章再設定
additional_hosts把其他內網 origin 映射到不同 hostname預設空陣列，只增加真正需要且已妥善驗證的服務
tunnel_name本機管理型 Tunnel 名稱，Cloudflare 帳號內必須唯一既有 Tunnel 正常時不要只為美觀改名
catch_all_service把未被前面 hostname 規則匹配的要求交給指定服務一般家庭不要開；範圍比明列 hostname 大
nginx_proxy_manager把 catch-all 指向該附加元件的內部位置；會忽略另填的 catch-all只有已理解反向代理路由時才使用
post_quantum要求 Tunnel 使用後量子混合金鑰交換，並限制為 QUIC可能受網路環境影響；不要當作排錯時的隨手開關
tunnel_token連接 Cloudflare 建立的遠端管理型 Tunnel視同密碼；設定後其他本機路由 options 會被忽略
run_parameters傳入文件允許的額外 cloudflared 執行參數進階排錯才改，記錄原值；無法覆寫附加元件已固定的參數
log_level控制附加元件腳本的日誌詳細度平常用預設 info；排錯暫用 debug 後再調回
兩種 log level：附加元件的 log_level 控制附加元件輸出；Tunnel 本身的詳細度可由允許的 run_parameters 之 --loglevel 調整。零基礎使用者先不要混用兩者。

儲存前的安全檢查

  1. 確認沒有多餘的公開入口

    逐筆核對 external_hostname 與 additional_hosts。不需要從外面使用的路由就不要建立；尤其避免直接暴露路由器、NAS 或其他管理後台。

  2. 檢查敏感欄位沒有外流

    密碼管理器可以保存 token，聊天軟體、公開 issue、截圖與共用文件不行。若 token 曾外洩，應在 Cloudflare 端撤銷或輪替，不要只把訊息刪掉。

  3. 避免廣泛 catch-all

    catch_all_service 與萬用 DNS 會擴大可到達範圍。若你只需要一個 Home Assistant hostname，就使用明確規則，不要為了「以後方便」先開萬用入口。

  4. 保留服務本身的登入保護

    Tunnel 解決從 Cloudflare 到家中的連線，不會自動替每個 origin 加上適合你的登入與權限。Home Assistant 仍要使用獨立帳號、強密碼與多因素驗證；其他服務也一樣。

  5. 安排可回復方式

    確保本機網址可用，記下最後一組正常的非敏感設定。遠端操作前先想好：如果 Tunnel 起不來，誰能在家中用本機入口復原。

驗收原則：一次修改、一次重啟、一次驗收。先確認這次改動穩定，再進入第 8、9 章新增 hostname。

Config 常見卡關

  1. 儲存後欄位又變回去

    先不要連按儲存。重新整理 Web GUI 與附加元件設定頁，確認是否有另一個舊分頁稍後覆寫。只保留一個編輯入口，再做一次小改動並等待重啟完成。

  2. 按下後 Web GUI 暫時打不開

    Save & Restart 會真的重新啟動附加元件，Ingress 暫時中斷是預期行為。回附加元件頁看狀態與 Logs；若反覆重啟，依第一個明確 validation 或 fatal 訊息回復剛改的欄位。

  3. 改了 hostname 但完全沒生效

    檢查是否已填 tunnel_token。遠端管理型 Tunnel 會忽略其他本機管理設定，hostname 與 public hostname 路由要到 Cloudflare Zero Trust 修改。

  4. 日誌太多或看不出重點

    先用 info 重現一次並記下時間；必要時短暫改為 debug。只擷取錯誤前後的必要片段並遮蔽 hostname、IP、token、憑證與授權網址，完成後調回 info。

  5. 設定驗證失敗

    比對欄位格式：hostname 不帶協定，additional host 的 service 要帶 http:// 或 https://，布林值不要當文字。回復最後一次正常值，避免猜測加入未在 schema 中的欄位。

常見問題

Config 與附加元件設定頁，哪一邊才是真的？
兩邊都在讀寫同一組 Supervisor options；options 本身才是唯一事實來源。不要同時在兩個舊分頁編輯，儲存後重新整理核對即可。
Save & Restart 可以只存檔、不重啟嗎？
這個按鈕的設計就是寫入 Supervisor options 後重新啟動附加元件。若現在不能接受 Tunnel 短暫中斷，就先不要按，改在維護時段操作。
平常應該把 log_level 留在 debug 嗎？
不建議。上游文件建議一般情況使用預設 info。debug 適合短期排錯，內容更多，也更需要在分享前檢查敏感資訊。
只想公開其他服務，可以不填 external_hostname 嗎？
可以。本機管理型 Tunnel 可讓 external_hostname 留空，只設定 additional_hosts。但每一個額外服務都要先做第 9 章的必要性與安全檢查。
使用 tunnel_token 後，還要在 Config 填 additional_hosts 嗎？
不用依賴那些欄位。依附加元件文件，設定 tunnel_token 的遠端管理型模式會忽略其他 options；公開 hostname 與服務路由應在 Cloudflare 介面管理。
